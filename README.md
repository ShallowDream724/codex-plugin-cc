# Codex Subagents

在 Claude Code 中调用 Codex 子代理执行任务，并在侧栏查看消息、工具调用和文件修改。支持继续原对话、直接给子代理发消息、等待答复和停止任务。

仓库：[ShallowDream724/codex-plugin-cc](https://github.com/ShallowDream724/codex-plugin-cc)。本插件的开发、文档与安装入口统一使用默认 **main** 分支。

当前版本为 **0.2.0-rc.28**。本插件从 `y-cruce/codex-plugin-cc` 精简而来，运行时依赖 Node.js 和 Codex CLI。

## 安装条件

- Node.js 22 或更新版本。
- 已配置并登录的 Codex CLI **0.169.0 或更新版本**。使用原生线程、当前上下文注入和历史分页接口。
- 使用下表列出的 Claude Code 界面，并更新到近期版本。

使用 Codex 默认模型目录即可，无需准备 `models.json`。Claude 调用的默认探子随插件提供，使用 `gpt-6-luna` 和 `medium`，要求账号能使用该模型。用户无需创建 `~/.codex/agents/default.toml`。

## 安装与首次使用

在 Claude Code 对话中依次执行以下两条命令（不是在系统终端执行）：

```text
/plugin marketplace add ShallowDream724/codex-plugin-cc
/plugin install codex-subagents@codex-subagents
```

安装后重启 Claude Code，打开需要工作的项目，在对话中加载：

```text
/codex-subagents:codex-delegation
```

然后直接描述任务，例如：

```text
让 Codex 创建一个子代理，只读检查当前项目的结构和主要问题，不修改文件，完成后向你汇报。
```

后续可以继续说「让刚才的 Codex 子代理继续检查测试覆盖」。插件沿用该代理的原生对话，无须每次重新创建。

- 点击桌面输入框下方状态栏中的「Codex·数量」小按钮打开代理总列表，再点一次收起侧栏；也可输入 `/codex-agents` 打开列表。经典终端入口仍位于输入框上方。工具记录中的代理名称仍可直接打开对应对话。
- 列表包含当前 Claude 会话创建或接入、尚未清理的直属代理，按「已开启」「完成」分组，各组最近活动在前。同一线程反复复用仍是一项；数量是未清理的总数，完成不会使它减少。显示图标、单行省略名称和相对时间；每组超过 50 个可翻页。未显式命名的代理使用原 Codex 对话名称；旧记录后台补读原生时间，确实没有可用时间时才显示「时间未记录」。
- 点击列表项会打开该代理的最新消息和输入框。对话顶部的「代理列表」和输入区的「‹ 列表」都可返回。草稿按代理保留，列表也会记住页码和滚动位置。
- 在侧栏直接发消息：运行中指导当前轮，空闲时继续原对话。
- 输入 `/codex-stop` 立即停止当前 Claude 会话的全部 Codex 代理及其后代；Claude 自己的停止按钮保持原行为。

已安装用户可在系统终端更新。第一条命令也会将此前指定的 `feat/codex-subagents` 来源切换到默认分支，无须卸载插件：

```bash
claude plugin marketplace add ShallowDream724/codex-plugin-cc
claude plugin update codex-subagents@codex-subagents
```

更新后重启 Claude Code，继续原对话即可，无须新建聊天。插件更新不会自动续跑已经停止的任务。

## 上下文范围

默认 `context_mode: available`：继承 Claude 公开接口当前能提供的上下文。已核验内核最多返回最近 4,096 条正规化后的 API 消息，并可能向后移动到合适的用户消息边界。它不保证包含整段会话的全部历史，因此不用 `all` 命名。

4,096 数的是 API 消息，不是人类对话轮数或工具执行次数。一条消息可以包含多个工具块；一次执行通常包含调用和结果。压缩后的当前摘要、保留消息和后续内容仍由 Claude 自己选择，插件不回填已丢弃的历史、不额外请求摘要、不估算 token。

`context_mode: none` 用于只需要当前任务说明的独立工作。Codex 如果缺少必要细节，会通过问题回传给 Claude。

继承的消息通过 Claude 的公开 HTTP 接口直送本机。若 Claude 配置了 HTTP 代理，请让 `127.0.0.1` 走直连。导出被宿主拒绝时，插件会说明原因并停止这次派发。

继承的 Claude 消息按原来的角色和顺序进入 Codex 的模型上下文。新线程的可见对话从 Claude 派发的任务开始。通过深链接继续已有 Codex 线程时，侧栏保留该线程原有的可见对话。

新建代理默认使用 Claude 当前项目目录，也可显式指定绝对路径。插件在首次派发任务前核对供应商目录。指定的型号已隐藏时，返回完整可见列表供重新选择。`followup_task` 使用 `target` 和 `message` 续接原 Codex 线程，沿用其目录、历史及模型。

如果原模型已被隐藏，或供应商明确拒绝该模型，失败信息会说明原生轮次是否已经启动。目录读取成功时，会列出该线程供应商目录中的完整可见模型，以及本次可选的恢复目标。只有同一模型家族、完整后缀一致且版本更新的可选型号才会被提示为「可能的新模型」，最多提示一项。有可选型号但缺少推荐时，Claude 请尚未选定型号的用户选择。选定后，Claude 将对应的 `target` 和原来的 `message` 交给 `followup_task`，在原 Codex 线程继续。

目录读取失败或暂时无可选型号时，Claude 可以显式调用 `list_agents` 只读查询当前模型、状态及恢复选项。供应商明确拒绝可见型号时，先核对线程绑定的供应商和准确模型 ID，再确认当前账号是否获准使用该 ID。自定义目录决定列表显示，上游供应商决定账号能否调用。若该型号仍可见，用户确认已恢复访问后可用 `retry_after_access_fix` 中对应的独立目标重试。

仅因原模型从目录消失而停下、且尚未完成恢复的代理，在显式重试时会重新检查该模型。替换模型的轮次被 Codex 接收后，后续续接沿用替换模型，例如由 Sol 接管后，旧 Astra 重新出现在目录也不会触发切回或通知。再次提交已用的恢复目标时，反馈会指出已接收的模型和轮次，本次不会再次发送任务。

首次接入闲置的深链接时，模型预检失败仍保留线程登记。恢复后原来的深链接和代理 ID 继续有效。用户暂停、待处理的审批及正在执行的轮次仍按各自的状态处理。

侧栏区分「新建」「继承 Claude」「Codex 历史」三种来源，后续续接不会改变来源；缺少可靠来源信息的旧登记显示「来源未记录」。继承的 Claude 窗口供模型使用，不再作为一串重复气泡显示。接入 Codex 深链接时则显示该线程原有的消息和工具历史，按需分页读取，包括原生接口仍保留的压缩前记录。深链接续接不同时注入 Claude 窗口；需要补充的任务信息可以写在续接消息里。

## 本地开发加载

从当前目录加载到一次 Claude Code 会话：

```bash
claude --plugin-dir "/absolute/path/to/codex-subagents"
```

在 Claude 中加载 `/codex-subagents:codex-delegation`，然后正常说明工作。工具定义按需通过 ToolSearch 加载。协作指引集中在 [审阅稿](docs/GUIDANCE_REVIEW.md)。

开发期间安装到日常会话时，先将已提交版本打包，解压到独立的版本目录，再以该目录作为本地 marketplace。不要将正在编辑的工作区作为长期安装来源；宿主会直接读取目录，运行中的 helper 会拒绝混用不同版本。更新后重启 Claude，再继续原对话。

## 工具

| 工具 | 行为 |
|---|---|
| `spawn_agent` | 新建 Codex；可选 `role: default` 使用 Luna medium 的独立只读探子 |
| `send_message` | 运行时 steering；空闲时仅将消息写入原历史 |
| `followup_task` | 指导运行中的代理，或在原线程开启下一轮。支持通过 Codex 深链接接入闲置外部对话 |
| `wait_agent` | 在程序里等待重要事件，不反复采样 Claude |
| `answer_agent` | 按原请求 ID 回答问题或审批 |
| `interrupt_agent` | 中断当前轮，保留历史与文件修改 |
| `close_agent` | 关闭指定代理，或批量关闭并保留指定集合；保留原生历史 |
| `list_agents` | 只读查询代理 ID、当前模型、状态及待恢复代理的可选型号 |
| `list_models` | 读取 Codex 模型目录、描述、选型提示和支持的推理档位 |

默认等待。只有确有必要的独立工作才并行。Codex 仍能调用自己的原生子代理；其工具过程和结果不会逐层灌入 Claude。必要的后代提问或审批会归到直接代理，由同一请求 ID 回答。

`wait_agent.timeout_ms` 只限制本次等待，到时 Codex 继续工作。省略时等到有事件或代理均已空闲。对空闲代理发消息会返回 `stored`，消息已写入历史，下次启动时可读。运行中收到指导会返回 `steered` 和轮次 ID。如果确认返回时该轮已经结束，插件返回 `steer_unconfirmed`，提示先查看同一代理再决定是否重发。答复格式有误时，`answer_agent` 返回 `invalid_answer` 和正确的 `reply_format`。

Codex 必须得到 Claude 的答复才能继续时，应调用原生 `request_user_input`；请求保持待答，由 Claude 用 `answer_agent` 回答后继续。`notify_parent` 只发送协作通知，不等待回复；普通 `send_message` 不能解除待答请求。需要这类互动的任务应使用普通代理，单轮只读的 `role: default` 不启用主动提问。

等待覆盖整个会话。代理事件按 `agent_id` 判断归属，暂停全部则产生一条会话级事件。同一时刻只保留一批待交付事件，并发等待立即告知已有等待者。事件进入 Claude 的实际历史后才持久确认；正常重启只扫描一次当前窗口补确认，不反复读取长上下文。取消、拒收或无法确认时保留事件，后续仍用原 `seq` 交付，不重新执行任务。

较长的 `timeout_ms` 是等待上限，不要求固定等满。程序内部每段长轮询最多 25 秒，完成、问题和相关状态变化可提前唤醒。一个代理完成后，其他父级任务、仍在运行的后代或待回答请求可能继续使会话处于等待状态；界面出现最终文字也不等于原生轮次已经发出结束事件。

相邻到达的结果会合并进同一条自动通知，保留各代理的完整结果。Claude 忙碌时，插件在主模型发出工具调用后或该轮写入工具结果后，检查并追加可交付的通知，供后续模型请求读取。Claude 正常结束后立即检查，空闲时每 10 秒也会检查。已追加的问题或审批如果在轮次结束时仍待答、未进入后续模型请求且无法随下一条实际通知一起处理，插件可补一条提示。启动失败若已由工具结果交付，则该结果就是此次反馈。用户取消 Claude 的轮次后，自动交付等到用户开启下一轮。`wait_agent` 与自动通知共用领取和确认机制，先确认已保留的等待结果，再领取其他事件。

右栏消息正文不通知 Claude；空闲时开启的独立用户轮次，其自动完成结果也不通知。用户向运行中的父级任务发送指导不会改变该轮归属或完成通知，显式 `notify_parent` 仍可发出协作消息。

rc.22 不再注册可能被 `cc-plugin-sec-default` 跳过的 `classic.PostToolBatch`，改用公开的模型响应和工具结果事件。无需关闭安全模块或修改组织策略；宿主仍可拒绝插件追加的通知，拒绝时事件保留待后续获取。

模型目录由外部 Codex CLI 管理。配置了 `model_catalog_json` 时，该文件决定列表；把条目的 `visibility` 改为 `hide` 后，重启桥接进程即可隐藏。使用默认配置时，由 Codex 自己提供目录。插件不内置 CLI 或另设白名单，不过滤 ultra 等原生档位。额外选型提示位于 `config/guidance.json`，未列在该文件里的新模型仍正常返回原始描述和档位。CLI 升级与插件升级相互独立。更新插件后，新建任务可使用更新的选型建议；已有线程继续沿用当前模型配置。

## 默认角色、并发与权限

为普通代理指定 `reasoning_effort: "high"`，首轮及重启后续接的轮次都会使用 `high`。省略该参数时使用 Codex 的配置档位。

`spawn_agent({"role":"default","message":"…"})` 使用 Luna medium 和任务独立上下文；省略 model、reasoning_effort、context_mode 即可。角色负责快速检索、整理和事实核验，单轮交付；不修改文件、不派生子代理、不生图。普通 Codex 保留多轮协作、原生子代理和其账户支持的生图能力。

插件不覆盖用户的 Codex 原生角色。只有可靠确认没有自定义角色配置时，才给新建普通线程提供同款原生 default 角色；发现任何角色 TOML、子目录或无法确认的配置时保留原生行为。你的原生 default 若已配置，将继续生效。

宿主的插件设置提供两个用户选项，它们不会成为 Claude 的工具参数：

| 设置 | 默认 | 含义 |
|---|---|---|
| `maxActiveAgents` | `5` | 当前 Claude 会话的直接活动任务上限，可设 1–7；历史记录不占名额 |
| `permissionsMode` | `full-access` | 完全访问；可改为 `auto-review`（Codex 自动审查）或 `ask`（请求批准） |

启动中、运行中、等待回答、压缩中、状态不明的任务都保守占用名额；有活动后代的根代理也占名额。Codex 自己的后代不单独计入直接任务上限。角色的只读职责不另设只读沙箱。权限及名额配置变化需要重启当前 helper，不能静默改变正在运行的任务。

完全访问明确设置 `danger-full-access` 和 `never`。其他两种模式设置 `workspace-write`、`on-request`，分别使用原生 `auto_review` 或 `user` 审批者。命令规则、组织约束及工具宿主授权仍由 Codex 和相应工具决定；错误保留来源，不笼统归为权限不足。

批量关闭示例：`{"targets":["agent-a","agent-b"]}`，或 `{"targets":"all","except":["keep-a","keep-b"]}`。只处理调用开始时的名单，活动及待处理请求的代理会跳过；给 Claude 的结果仅包含关闭数量和例外，不重复列出全部成功 ID。

## 查看过程

派发和完成记录中的代理名称可点击；`/codex-agents` 打开当前会话的代理总列表，不调用模型。桌面入口使用公开 SessionMode 状态栏，避免 AbovePrompt 的整行灰框；终端保留 AbovePrompt 并在调查问卷出现时让位。不向 APP 最上排工具栏注入按钮。详情是一条连续对话，显示往来消息、Codex 进度、命令输出、工具输入输出、文件 diff 和图片文件路径。向上滚动补读更早记录，新消息在末尾追加。工具详情按需展开，长工具输出分段读取；下级代理只显示委派记录。

对话保存在原生 Codex 线程中；界面按需读取，已加载消息保留用于往返浏览。历史按内容量批量读取并提前缓存下一段；显示窗口以约 8 万字符的整树预算为上限，包含正文、工具输出、图片数据和界面控件，不是聊天历史的总长度上限。另有节点和条目数量保护，上万条历史不会一次画进界面。长消息可一次展开或收起；超大内容仍分段显示，原文和模型历史不截断。查看过程不会确认或消耗 Claude 的消息。从列表或聊天记录点进代理时，面板定位到输入框和底栏。上滚可阅读历史，手动滚回底部或点击“回到最新消息”即可继续跟随。底栏的“‹ 列表”可直接返回代理列表。直接发送消息后也会跟随末尾。工具折叠状态按代理保留，关闭面板后任务继续运行。

rc.13 修复了持续追加内容时的跟随滚动：停留在底部时自动跟随，主动向上阅读时暂停，回到底部后恢复。文件记录依据原生操作区分“已创建”“已编辑”“已删除”和重命名；创建、删除也显示带行号的红绿 Diff。缺少可靠差异时不填造 `+0 -0`，不会根据命令名称或正文里的列表符号猜测变更。

历史在接近边缘时自动补入，等待时显示加载圈，无须点击加载按钮。有空间时直接追加；不足时先从远离阅读位置的一侧腾出空间，并保留相邻的已读内容。停在顶部不会仅因加载完成又自动触发下一轮；离开边缘再返回可继续加载。短页面初次可自动补齐一批。折叠工具保留已有分组；回到最新消息按钮保持底部居中并带悬停说明。直接发送的消息显示 `User`，已识别的父代理消息显示 `Claude`，来源未记录的旧消息显示“消息”。插件的复制按钮在成功后显示勾号和“已复制”，失败时显示原因，可再次点击重试。

Codex 的普通最终答复会作为正文出现在右栏；父级任务完成时交给 Claude 的结果来自同一段答复。rc.13 仅为原生 `final_answer` 且有完成证据的答复提供复制图标，复制完整原文，不夹带过程和工具记录。Claude 和直接用户消息等正文均使用原生 Markdown。

`notify_parent` 和已识别的原生消息发送调用展开后直接显示通信正文，参数与投递结果保留在 `</>` 中。短正文即时显示；长消息和通信正文一次展开全文并可收起。超过侧栏显示容量的正文提供预览和完整 Markdown 文件链接，重新展开复用缓存。文件是临时快照，原生历史不变。发送、读取或复制失败仍明确显示。后代代理的完整对话不递归展示。这些改动包含在 rc.13 本地候选版中。

正文使用宿主 Markdown，可显示表格、列表、引用和带语言的代码块。当前插件侧栏没有任意 HTML/iframe 网页嵌入入口；HTML 代码可以作为源码查看，但不会在消息里直接变成交互网页。这是该插件界面接口的能力边界，不能理解为 Claude 所有功能都禁止 HTML。[官方组件清单](https://code.claude.com/docs/en/plugins/mods/reference#elements)

展示副本会保守修正中文粗体闭合的特定格式，并保护代码、数学与链接；原始历史和复制原文不变。

展开对应工具后才按需读取图片，PNG 使用原生图片组件，多图横排并换行；点击缩略图可在同一面板放大，右上角 × 返回原工具位置。待发送的 PNG 剪贴板图片和已发送的 PNG 附件也可预览。Windows 上 JPEG、GIF 和 BMP 按需转成有界 PNG 预览，GIF 标注首帧；无法解码的格式保留原图链接，原图不会修改。

工具将 MCP 图片结果包装成 JSON 字符串时，也会识别并按图片处理；不会把图片的 base64 数据作为正文展示。混合结果中的文字和错误仍保留。rc.15 中：当原生事件里的图片数据被截断时，尝试从同一线程、轮次和调用的原生记录恢复完整图片；无法恢复时明确提示。

当前没有分支按钮或分支列表。

## 复用原生对话

把线程 ID 或 `codex://threads/<id>` 作为 `followup_task.target`。插件读取原生元数据、保留 cwd 和历史，登记后在原线程继续，不复制新的 Claude 上下文。活跃或状态未确认的外部线程不能接入；原生客户端的并发限制仍然生效。

插件的 `agent_id` 属于当前 Claude 会话；跨会话继续时使用原始 Codex `thread_id` 或线程链接。若目标不在当前登记中，可先用 `list_agents` 查当前可用 ID。查找失败并不能证明发生了会话分支，也不代表 Codex 历史丢失；连接超时、错误地址、已清理的代理等原因需要分别判断。

任务已完成也可能仍由另一 Codex 连接持有线程写入锁。此时续接明确返回 `active native writer`，保留原代理和历史；需要原连接释放线程后再重试，插件不会抢锁或另建替代任务。同一 helper 中已经加载的代理直接继续下一轮，无须重复恢复。

旧对话可能保存原客户端提供的动态工具。0.169 的 resume/fork 接口不能替换这些工具；插件会报告可读取到的工具元数据及 `client_tools_unavailable`，无法执行的调用明确返回失败，不伪造结果，也不自动另开替代任务。原生 CLI/MCP 工具与原客户端专属工具应分别验收。

## 桌面、浏览器和图像生成

原生 Computer Use/浏览器功能需要安装并启用对应官方插件、保持 Codex App 运行，并建立实际连接。插件不会自动打开 App，也不把工具已列出当作桌面或浏览器已连接；App 未运行或连接失败时，这些能力不可用，普通任务不受影响。

`npm run doctor` 可只读查询 CLI 版本、模型档位和 MCP 工具注册情况；`npm run doctor -- --json` 输出精简诊断。它不创建任务、不请求模型、不调用电脑或浏览器工具，输出明确注明宿主连接尚未验证。

原生生图是否可用由 Codex 的模型、账户、后端和功能开关共同决定。当前原生入口由服务端选择尺寸，插件不声明固定 1.5K 上限，不额外调用生图供应商。默认探子禁用生图；生成文件仍由 Codex 管理。

## 上下文与缓存

每次新建都重新读取 Claude 的当前可用窗口。连续四五次压缩后，在接口返回范围内传入当前摘要、明确保留的消息及后续消息，不拼接此前快照。返回的用户消息、Claude 回复、工具参数和结果不再被插件截短；thinking 不传。工具调用作为历史证据，不会被重新执行。图片字节只作为图片传递一次，不另塞一份 base64 正文。

已记录在有效窗口里的项目说明和引用会随消息传递；Claude 独立的系统提示词和工具定义不复制。Codex 使用自己的运行时和工具。无法表示的二进制附件（例如原始 PDF document block）会明确报错，避免静默丢失；可以改用已提取文本或明确指定文件任务。

初始快照只注入一次。续接不重新导入 Claude 历史，也不修改旧系统提示词或工具描述。通知只追加。插件不估算 token；真实超限错误触发最多一次 Codex 原生压缩恢复。压缩本身会形成新历史前缀，应与普通续接的缓存命中分开验收。

Codex 自己按原生规则加载 `CODEX_HOME` 下的全局 AGENTS.md 和工作目录适用的项目指引；插件不代替这套加载流程。MCP、插件和工具权限沿用实际 Codex 环境，不能把某个桌面对话中的专属工具视为 CLI 自动拥有。详见 [原生指引发现规则](https://developers.openai.com/codex/guides/agents-md)。

新建返回的 `context_snapshot.preview` 展示实际继承范围的首尾：各最多 160 个 Unicode 字符，带原窗口中的消息序号、角色和中间省略条数。`preview_only` 表明省略只发生在预览；注入 Codex 的历史不因此裁剪。thinking、图片字节和工具参数不会出现在预览中。预览只随新建结果返回，不在后续状态列表里重复。

## 状态与生命周期

Claude 界面显示简短生命周期记录，过程按需展开。普通工具调用、进度和压缩开始/结束只在侧栏显示，不向 Claude 发消息，也不会单独结束 `wait_agent` 的等待。协调消息、问题、审批和完成/失败/中断仍进入事件队列；真正的压缩失败按任务失败通知。旧版排队但尚未交付的压缩状态会在恢复或领取时清理。没有新增给模型的过程读取工具，也没有递归子代理日志面板。

点击代理名称打开详情，或从输入框旁的 Codex 入口及 `/codex-agents` 总列表进入。在详情中直接发送消息或停止任务，无需先让 Claude 调工具。运行中发送会指导当前轮；空闲时在原对话继续。私人消息正文不推送给 Claude；独立用户轮次的自动结果也不推送，但均保存在同一 Codex 线程。用户指导父级任务不会改变其归属；Claude 可以用 `followup_task` 指导仍在运行的独立用户轮次，仅在原生接口确认同一轮接受时转交归属。若完成与请求交错，结果可能未确认，不会用迟到回执覆盖归属。显式向父代理提问、协作消息以及停止事实仍按原路径交付。遇到待回答的问题或审批，应先处理原请求，普通消息不会冒充审批。

界面使用 Claude Code 的公开原生组件：主线程是图标与可点击名字组成的生命周期记录，代理详情呈现正文、合并工具组、文件增删和底部输入。短消息气泡靠右并随内容收窄，长消息在侧栏宽度内换行。公式展示先识别代码、转义和数学片段，仅将明确的 `\[...\]` 块公式转成宿主支持的 `$$`，公式内部及原生历史不改；`\(...\)` 行内公式保留给宿主解析，不盲目改成单美元符。Mermaid 由宿主渲染，终端保留可读源码。通用交互 HTML 保留为独立产物，当前不嵌入任意 HTML 页面。

输入区显示权限模式、模型、推理档位与 Codex 最近一次回报的上下文比例；缺少真实数据时不显示比例。提交按钮在有待发送内容时显示上箭头，工作中且输入为空时显示停止方块。通过 `+` 选择图片或文件，也可在不支持系统选择器的平台输入绝对路径。图片作为原生图片输入，普通文件作为同一文件系统中的路径供 Codex 读取；不会把文件内容复制给 Claude，不移动原文件。每条消息最多 20 个附件，发送失败保留草稿和附件。Windows 使用独立系统文件选择框，其他平台使用路径输入。

Windows 的“粘贴附件”读取剪贴板里的截图或复制的文件，只在点击时执行；截图保存为本地临时 PNG。当前宿主公开的插件 Input 不传图片粘贴或文件拖放事件，因此侧栏暂不支持截图 Ctrl+V 和拖入文件。输入与操作栏组成一个区域；位置和整体滚动由宿主管理，公开 Pane 没有固定底部输入槽。

Desktop 使用全宽原生输入框，省略 `submitLabel` 隐藏框旁提交键，Enter 发送，空白 Enter 不停止任务；原生输入法与换行仍交给宿主。附件与用量栏在下方留小间距，不叠加第二层外框；附件名称缩短显示、自动换行，完整路径保持不变。上下文用量取自 Codex 的实际 token 指标，悬停圆环显示明细。模型名右侧的圆形发送／停止控件由公开 Client 的 Box/Text 绘制和处理鼠标、键盘事件：有待发送内容时为箭头，运行且没有待发内容时为方块；动作仍由 hooks 校验当前代理状态。没有重写文本编辑器或修改宿主。终端使用原生输入和简洁按钮。

文件差异在桌面侧栏以单列行号和红绿底色展示，不显示 `@@` 和补丁行首的增减标记；实际代码里的加减符号保留。删除行使用旧行号，其他行使用新行号。大型差异展开后作为连续历史的一部分滚动读取，已读数据缓存并预取后续两批；无需手动切换文件差异内容页。无法解析的原始格式回退源码。右上角仅一个复制入口，收集并复制完整原始差异及换行。终端同样按连续片段展示，长行采用宿主支持的换行方式；普通工具输出仍可分页。

侧栏的停止按钮暂停选中的代理及其后代，保留历史与已产生的文件改动，其他代理继续运行。界面区分正在停止、已停止与未确认。Claude 只收到一条结果，例如「用户暂停了 Codex 代理 Astra 及其所有子代理。」停止结果确实需要用户处理时，这条结果改为说明未确认和下一步。暂停标记跨重启和关闭登记保留；停止确认后，用户直接发消息即可恢复。Claude 的停止按钮、关闭详情和取消等待各自独立；结束整个会话则按下面的生命周期规则清理。

在代理列表点击红色「暂停全部 Codex」并确认，或输入 `/codex-stop`，即可暂停当前 Claude 会话中的全部 Codex 代理及其后代。列表显示处理进度和各代理状态。有正在工作的代理时，确认后 Claude 只收到一条会话级结果「用户暂停了本会话中的所有 Codex 代理。」空闲和已完成的代理也会标记为暂停。插件先保存本次名单的暂停状态，再并发中断需要停止的工作。暂停操作仅连接已有 helper，无法联系时界面会报告结果未确认。

状态默认位于 `~/.claude/codex-subagents/<session-hash>/`。只保存线程标识、快照摘要、状态、未确认的重要事件和实际 usage，不另存整份 Claude 快照。Codex 的原生线程历史由 Codex 自己持久化。

不再需要的失败或已完成代理可用 `close_agent` 清理；有活动任务、待回答请求或活动后代时保留。关闭后旧插件代理 ID 不再可用，但可用原生线程 ID 重新接入；原生历史始终保留。

正常会话结束会关闭所属桥接进程；宿主失联后约 90 秒租约过期，清理所属任务。等待和每 10 秒的本机后台观察会续租；它不是任务执行时限，也不产生模型心跳。下次由 `followup_task` 恢复原线程，不自动重跑旧任务。中断等待只结束等待订阅，不中断正在工作的 Codex。

断电或系统重启后，恢复的是代理登记和原生历史，不会自动让全部代理继续工作。未被用户手动暂停的代理，可由 Claude 明确对所需代理调用 `followup_task` 续接；用户单独或批量暂停的标记仍保留，需用户直接恢复。

每个会话的桥接进程拥有整个生命周期的独占锁。同协议且支持空闲关闭的 helper 在确认没有活动工作和在途动作后可自动更换版本；活动工作不会因插件更新被强行停止。不兼容或不支持空闲升级的旧版本需重启会话。机器从较长暂停恢复时有额外续租宽限。回执按动作单独保存，避免长线程反复重写全部旧回执；旧版本数据会自动迁移，原文件保留为备份。

若启动下一轮时回复丢失，代理会标为 `unknown`，避免盲目重复开工。对同一代理显式发送、续接、中断或关闭时，插件先只读查询线程状态，必要时恢复订阅；状态明确后才执行该操作。单个代理的普通启动失败不会终止其他代理。无法持久保存状态时停止服务，让已保存记录用于恢复。

可配置环境变量：`CODEX_SUBAGENTS_NODE_COMMAND`、`CODEX_SUBAGENTS_CODEX_COMMAND`、`CODEX_SUBAGENTS_STATE_DIR`。显式 `CODEX_SUBAGENTS_SETTINGS` JSON 可覆盖宿主插件设置，例如 `{"maxActiveAgents":7,"permissionsMode":"auto-review"}`；未知键或非法值明确报错。可执行文件路径与参数分开传递，不通过 shell 拼接。保持用户现有 Codex 登录，不启用 fast/priority。

经验性内容维护在 `config/guidance.json` 和 skill 中；修改后运行 `node scripts/guidance.mjs`，同步生成原生 default 配置与完整审阅稿。`npm run check` 会检查它们一致。

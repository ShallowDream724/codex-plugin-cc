## 消息与压缩

| 场景 | 合成历史记录 | 宿主导出的 API 消息 | 注入 Codex 的历史项 |
|---|---:|---:|---:|
| 连续五个压缩边界 | 21：8 user、8 assistant、5 boundary | 9：4 user、5 assistant | 10，含 1 条固定范围说明 |
| 超过接口条数上限 | 4,202：各 2,101 条 user / assistant | 4,096：各 2,048 条 | 4,097，含 1 条固定范围说明 |

压缩场景断言：保留当前有效摘要、明确保留的消息、工具参数及长结果末尾；不恢复已丢弃内容，不重复拼接旧摘要。上限场景断言：早期标记被宿主排除，窗口内标记保留。这里验证的是宿主对合成压缩记录的读取行为，没有让真实模型生成摘要。

4,096 是正规化 API 消息条数，不能换算成人类轮数或工具次数。多个工具调用可位于一条 assistant 消息，多个结果也可位于一条 user 消息；压缩边界本身不是一轮普通对话。

## 协作与故障

本地测试覆盖同线程续接、运行中 steering、空闲消息不启动推理、提问与审批的精确 ID、后代提问路由及过程过滤、压缩恢复上限、中断竞态、断线、重启和重复请求。真实宿主离线场景另走通新建 → 等待问题 → 回答 → 等待完成。

0.1.1 增加首尾预览与 Unicode 边界、已关闭代理持久化及迟到事件、关闭与发送的竞态、限时等待不终止任务、无效回答的重试格式等测试。预览不改变完整历史或 digest；新版本检查仍未发起真实模型请求。

0.1.2 增加最终历史确认、部分/改写结果不误确认、离线补确认、并发 wait 与提示互斥、取消在途、不兼容 helper、并发启动锁、初始化掉线、暂停后续租、审批允许列表、unknown 状态的有限读取恢复、代理间故障隔离及持久化错误测试。回执迁移与 300 个连续独立动作验证旧回执不被全量重写；当前轮次去重测试验证旧任务迟到事件不接管新任务。

真实模型效果、供应商缓存读写和 Desktop 的加载与通知留给使用者按 [手动验收](ACCEPTANCE.md) 检查，自动测试不会触发这些调用。

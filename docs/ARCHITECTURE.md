# 架构与边界

## 模块

`hooks/register.js` 是 Claude mod：注册九个按需工具，读取宿主公开接口提供的当前快照，等待重要事件并确认最终保留消息。`hooks/bridge.js` 仅提供静态导入的本机通信；UI 使用它不会进入模型交付确认流程。

`hooks/rows.js` 只改写工具调用和本插件通知的显示：不同代理图标与可点击名称组成简短生命周期记录，展开宿主完整记录时保留原始输出。`hooks/ui.js` 使用宿主公开的 Pane、文本、输入与展开组件呈现代理对话，提供 `/codex-agents` 键盘入口。`hooks/action-control.js` 仅绘制圆形发送／停止控件，经 `ui.message` 通知 hooks，hooks 再按当前选中代理、草稿和动作状态执行；没有模型工具或独立文本编辑器。`runtime/activity.mjs` 是独立只读投影，使用原生线程历史分页与有界实时缓存，不读写模型 pendingEvents。`shared/tool-output.mjs` 统一提取结果文本与有效结构化内容，跳过空协议占位；共享运行代码也纳入 helper 构建指纹。

`runtime/settings.mjs` 验证用户权限与活动名额，未知设置键拒绝。`runtime/roles.mjs` 读取唯一的经验指引源、保守判断原生 default fallback，并只读检查外部线程的首条 session_meta 动态工具元数据。角色 TOML 与完整审阅稿由 `scripts/guidance.mjs` 生成，检查脚本验证一致性。

`runtime/context.mjs` 是无状态转换器：校验消息格式，保留消息角色与顺序，跳过 thinking，把历史工具调用/结果转成不可执行证据，传递可表示媒体，生成稳定摘要。它既不读 JSONL，也不合并之前的快照。仅移除缓存控制字段等传输元数据，普通工具参数中同名字段保留。

`runtime/appserver-client.mjs` 负责 JSON-RPC stdio，包括初始化、反向请求、超时、分帧、背压、错误和关闭。`runtime/agents.mjs` 负责线程状态、审批、消息、续接和超限恢复。

`runtime/bridge.mjs` 和 `runtime/broker.mjs` 为每个 Claude 会话提供一个本机桥接进程。端口只监听 `127.0.0.1`，使用随机 bearer token；状态目录按 session ID 哈希隔离。上下文通过进程 stdin 和本机通道传递，不占 Claude 的工具参数输出。

`runtime/delivery.mjs` 管理单批交付租约、正文校验和精确确认；`hooks/delivery.js` 仅从宿主最终保留消息中识别本插件交付，兼容裸信封及 Claude 为本插件添加的两种精确固定包装（轮间、轮内）。不扫描任意嵌套 JSON；回执仍核对交付 ID 和完整事件内容。主界面通知行复用同一解析器。`runtime/receipts.mjs` 用单个动作对应单个原子文件保存回执，启动时迁移旧 `receipts.json`，不全量加载已有回执。

## 初始历史

顺序固定为 `thread/start` → `thread/inject_items` → `turn/start`。只在新线程注入一次。没有使用内部专用的 `thread/resume.history`，也没有借用会遍历整个源文件、截短工具内容的外部会话导入器。

直接使用宿主原有 `session.messages({as:'api'})`，不修改 Claude 安装。参数命名为 `context_mode: available`，含义是接口当前可用的窗口，不能声称完整生命周期历史。已核验内核最多取最近 4,096 条正规化消息，再移动到合适的用户消息边界；实际返回可能更少。原始记录数、响应数组短小或 token 估算均不被当成完整性证据。

例如内部 poll 事件和附件可以展开为多条 API 消息。插件不尝试猜测遗漏程度，也不将返回结果与磁盘旧日志拼接；初始说明会告知 Codex 这一范围，缺少必要信息时由 Codex 问 Claude。快照统计只报告实际返回和传递的数量，不报告虚构的总历史数或完整率。

范围预览从已经转换的历史投影首尾，排除固定说明和 thinking。每端最多 160 Unicode 字符，媒体仅类型占位，工具参数与证据信封不回流。预览不参与历史 digest，也不改变注入内容；只随 spawn 的响应及其幂等回执保存，不加入代理状态记录或日常 list 响应。

`contextSource` 在新建或外部采用时确定并持久化，投影为 `context_source`：none 为 new，available 为 claude，外部原生线程为 codex。续接不改来源。旧状态只依据明确的注入快照或外部线程标记迁移，否则为 unknown；不把缺少证据当作全新线程。

模型上下文与展示历史分别使用原生接口。Codex 0.169.0 的隔离离线探针验证 `thread/inject_items` 的继承消息不会进入 `thread/turns/list` / `thread/items/list`，因此不另按正文、首轮或条数隐藏消息；两轮实际任务及中间压缩记录仍可读取。外部采用不注入 Claude 快照，侧栏保留其原生展示历史。分页跨压缩记录继续，不把模型压缩边界当成历史终点。

## 协作

运行中消息使用 `turn/steer` 及 `expectedTurnId`，向当前任务加入指导，不调用停止。空闲消息通过 `thread/inject_items` 写入邮箱，返回 `stored`，但不启动推理；`followup_task` 才在原线程开新轮。判断依据是消息到达时的代理状态，不对测试消息或正文做语义分类。待回答问题或审批必须走 `answer_agent`，不通过 steering 绕过。

用户直接操作使用内部 `ui_send` / `ui_interrupt`，不新增模型工具；共享认证、动作回执和幂等检查，但绝不确认交付给 Claude 的事件。用户消息带固定来源前缀，活动投影显示为用户消息；运行中 steering，空闲时在原线程开启下一轮。直接对话正文和用户轮次的自动完成、失败、压缩等结果不进父代理 journal；每轮 `turnOrigin` 持久化，显式协作、问题/审批与用户停止事实保持交付。成功 steering 才转为用户轮次；RPC 未确认期间的终态暂存，明确失败或传输不明时恢复原父级归属。启动迁移只排除精确旧 send 回执及同 agent/turn 的自动结果，已进入 Claude 的对话不被修改。停止回执仍用短句区分请求、确认和未确认。普通 UI 轮询不产生事件。

用户直接对话后，同一 Codex 线程及其完整原生历史继续可用。用户轮次完成后，Claude 的 `followup_task` 在同一线程启动父级新轮次并恢复结果交付。仍活跃的用户轮次不能被父级新任务伪成功接管：返回确定未发送的 `private_turn_active`，待完成后使用同一代理重试；普通协调消息不会改变该轮归属。`wait_agent` 只等待父级工作或待回答请求；helper 的存活与名额仍统计全部工作，不能因私聊不通知父级就将其停掉。

私有轮次中的显式 `notify_parent` 仍是协作事件。Claude 空闲且宿主会话存活时，后台观察领取事件后通过 `prompt.submit` 提交，宿主可开始新的 Claude 轮次；观察周期为 10 秒。Codex 已完成后须先由用户侧栏消息等操作启动活动轮次，才能调用该工具；未运行的模型不会自行发送。这里沿用现有 Claude 会话与宿主调度，不另开 Claude API 客户端。

附件只由用户界面提交路径；后端校验本地普通文件、识别图片格式后，将图片转换成原生 `localImage`，普通文件以明确路径交给同一工作环境的 Codex。没有假设 `mention` 支持任意文件上传，也不向 Claude 传文件内容。文件校验前取得控制轮次标记，校验期间发生停止则取消发送。附件元数据与用户正文保存在原生历史中，活动投影恢复文件名及来源。选择器仅响应用户点击，Windows helper 用固定 PowerShell 代码，目录通过环境变量传入；不支持系统选择器时输入路径。

用户停止先持久化暂停意图，再中断该根及已知后代；新到的后代关联和启动事件也受停止约束。只有原生结束事件或元数据确认才解除活动占用并报告已停止；断线及不明状态保留未确认。暂停的原生线程 ID 跨关闭登记保留，重新采用也不会自动开工。用户恢复的独占标记阻止 Claude 的消息、续接与回答穿过恢复窗口；恢复成功前保留持久暂停标记，失败或结果不明时重新停止。关闭 UI 或取消等待不改变执行状态。

`/codex-stop` 通过 `command.register({immediate:true})` 与 `command.run` 直接调用内部 `ui_interrupt_all`，不增加模型工具或按钮，也不绑定 Claude 的本轮停止。批量停止固定根代理名单，先同步设置全部暂停屏障并共同等待持久化，再并发停止各自子树；事务期间拒绝新建/用户恢复，跨事务的未登记 adoption 用 epoch 拒绝。逐项失败不会阻止其他树，结果保留已停止/在停/未确认。操作经过同一用户动作回执与幂等路由，不确认 Claude 旧事件。无 endpoint/服务锁时返回离线且不启动 helper；已有但不可达或不兼容时保持未知，不伪报停完。

直接代理以 thread ID 索引。合法后代由 `parentThreadId` / `source.subAgent.thread_spawn.parent_thread_id` 关联。后代工具、推理、usage 和最终结果不传播；问题和审批保留源线程 ID，通过原始 JSON-RPC ID 回答。外部请求 ID 统一为字符串，内部仍保留原类型，避免数字 0 的丢失。

原生 `request_user_input` 在默认工作模式启用，用于必须得到回答才能继续的事项；简短 `notify_parent` 动态工具用于重要协调，不播报常规进度。重要设计问题、实质分歧或更优方案应在大量实施前沟通，不强制每项任务先讨论一轮。工程、验证和交付规范由适用的 AGENTS.md 等原生指引提供，协作提示不重复注入。Codex 自己的多代理能力保留。

`request_user_input` 保持原始服务端请求待答，代理进入 waiting，由 `answer_agent` 使用准确请求 ID 和响应结构解除等待。`notify_parent` 返回投递确认即结束该工具调用，不具有这一等待语义。协作指引明确两者区别，不依靠通知内容猜测是否需要重新启动已完成的代理。

`role: default` 使用配置的 Luna medium，hook 与 broker 在读取快照前将上下文模式归为 none，显式冲突则拒绝。该角色关闭原生子代理、生图和主动提问工具，角色职责要求只读、单轮、一次最终交付；其他角色不受这些开关影响。

直接活动任务默认最多 5 个（用户可设 1–7）。控制器在第一段异步操作前同步预留容量；starting、running、waiting、compacting、unknown、正在续接和有活动后代的根任务保守计数。完成、失败和停止且无其他活动的登记不占名额。宿主重启后先核实不明任务的原生状态，不能仅因重启就假定名额已释放。

权限由用户配置注入 helper，不在模型工具 schema 内。full-access 使用 danger-full-access/never；auto-review 与 ask 使用 workspace-write/on-request，分别采用 auto_review 与 user 审批者。新建和续接都应用相同设置；runtime 指纹包含设置与指引，不匹配的 helper 不会被静默复用。

## 等待与交付

工具调用内的程序长轮询每 25 秒续订一次，不返回给模型采样。背景观察用于续租和 UI 更新，不产生模型心跳。无等待者时，重要事件可以排队追加为宿主提示；有等待者时由等待工具交付。

后代轮次或已报告终态的根轮次发生结束状态变化后，在持久化完成时发内部 state 唤醒；不生成额外 Claude 消息，也不增加轮询。wait 在空 claim 后、返回 idle 前重新检查事件队列，防止完成事件恰好在空租约保存期间到达而被首轮漏报。其余后代或请求仍占用时继续等待，不把根的最终文字当成整棵任务树已停止。

显式 `timeout_ms` 使用宿主侧等待截止时间，每次本地订阅最多等待剩余时长；到期只返回 `timed_out`，不调用 `turn/interrupt`。已有事件优先交付，零时限可以读取已到达事件。默认省略时持续等待。

内部事件有单调序号、代理 ID、名称与轮次 ID。broker 在返回前确认原事件日志已保存，并为最多 32 条完整事件创建持久交付记录及租约；不截短单条结果。wait 与后台提示共用该租约，并发 wait 返回已有等待者状态，避免同一工具组互相等待。提示排队期间续租，取消或拒收只释放租约。

模型可见的 v1 交付投影移除顶层原生 turn/thread/item 路由 ID；保留代理名称、可操作的 agent/request ID、序号、类别及完整业务内容，未知业务字段和嵌套内容不删。新批次按实际投影内容计算确认 hash，旧批次仍核对旧原文，journal 不改写。Claude 为后台 prompt 加的英文框架来自宿主，插件不修改它；投影同时适用于 wait 和后台通知。

`session.append` 的 `await next(e)` 成功返回后，以最终保留消息为依据确认准确序列，不能仅凭工具返回、最大游标或 prompt receipt 删除事件。只读工具结果须匹配完整工具名和 tool_use_id；恢复时只扫描一次当前宿主 API 窗口。交付 ID 在当前会话的目录内查证，事件正文以 canonical hash 比对，部分保留只确认对应事件。0.1.1 的旧结果也必须与 journal 中完整事件相等。helper 离线或确认失败时保留证据，随下一次有效操作先补确认。

仅订阅本插件 wait 工具的 `tool-result` 与 `prompt` 两类追加事件，不注册全局追加拦截。内置安全插件跳过的 attachment、hook-context、compaction 等受保护事件与本插件确认无关；不更改安全插件顺序或策略。

公开宿主 API 的确认点是消息进入当前 conversation；恢复扫描依据宿主已经恢复的窗口。宿主与插件并无跨存储事务。异常中断下，无法确认的交付保留原 seq 重投，不静默丢弃；这不会重派模型任务。动作回执在副作用前落盘，按工具调用 ID 和输入指纹拒绝重复派发或 ID 混用；结果不明不自动重试。

## 恢复

普通超限错误不能被假定为会自动恢复。控制器等待失败轮结束，最多调用一次 `thread/compact/start`；确认压缩完成及其轮次结束后，只追加继续指令，不重新发送长任务或重注入快照。再次超限或压缩失败明确结束。父线程中断优先于恢复。

本机控制器重启后，曾运行的任务先标为状态不明，过期问题 ID 清除；查询原生元数据确认状态，显式 followup 才启动新轮。桥接关闭会清理客户端子进程。约 90 秒的租约代表宿主仍存活，由等待和后台观察续租；宿主失联时清理所属工作，不以原生任务活动替宿主无限续命。它只管理本插件的进程，不停止用户其他 Codex 会话。

turn/start 的明确 RPC 拒绝产生本代理 failed；没有启动证据的传输异常产生 unknown。若已观察到有效启动或完成，则保留真实状态。unknown 的显式操作先用 thread/read(includeTurns:false) 查询：idle/notLoaded 可恢复；active 必要时 resume(excludeTurns:true) 建立订阅，再读取最新一条无 items 的 turn。未确定状态前不自动重放任务。审批只能选择该请求 availableDecisions 提供的决策。

启动和服务锁使用 PID 与随机 owner token，锁内再次核验 endpoint；helper 在建立 Codex 连接前取得整个生命周期的服务锁。活 PID 不按文件年龄抢占。构建不一致时，仅同协议且声明 `idle_shutdown` 能力的 helper 可以自动更换：旧 helper 在同一个同步检查中确认没有活动工作和其他在途请求，并封闭新操作准入；调用方等待 endpoint 和服务锁都释放后启动新版本。活动任务、协议不兼容或旧 helper 未提供该能力时明确报错，不强行停止。连接关闭监听先于初始化，health 反映实际状态；休眠或长事件循环暂停后留续租宽限。上述升级保护不改变宿主失联租约的清理语义。

状态写入按微任务批合并，同一批调用共同等待保存结果；普通代理错误局部处理，真实持久化失败统一停止 helper。按当前任务/轮次管理去重集合，已回答、已过期和不可恢复的请求事件不继续交付。必要的动作 ID、关闭线程 ID 继续保留，以避免重复执行和迟到事件重新关联。

`close_agent` 只移除无活动轮次、待处理请求、并发操作和活动后代的终态代理。卸订阅后再次校验，清理本地所有权与待交付事件，保留原生历史；持久化已关闭线程 ID，避免迟到事件使记录复活。它不删除工作文件或 Codex 历史。

批量关闭先解析选择器并固定代理集合；except 仅用于 all，活动项逐项跳过。内部关闭 ID 列表用于 hook 过滤迟到交付，模型只收到数量和例外。卸订阅后若因新活动拒绝关闭，必须恢复订阅；恢复失败保留未加载/不明状态和可操作错误，不能伪装仍在收取事件。

外部续接支持原生 UUID 或 codex 深链接，按原生 cwd 与历史登记，不再注入 Claude 上下文。同一目标的首次登记串行，活跃/不明外部线程拒绝接入。0.169 不允许在 resume/fork 替换原客户端动态工具，接入结果明确报告这一限制；不支持的旧工具调用返回解释，并按工具去重发出注意事件，不自动重派任务。

同连接的已加载代理直接开始下一轮；重启或卸载后才恢复线程。已完成状态不代表原生 writer 已释放。RPC 错误保留方法、错误码及已识别的安全诊断（writer 占用、归档、缺少历史和先恢复原生父代理），不透传任意错误 payload。writer 冲突不自动抢占、删除锁、重放任务或建立替代线程。

## 显示边界

仅直接代理的事件进入活动投影；推理正文不展示，后代细节不递归读取。消息、工具、命令、文件修改及图片文件信息按类型格式化。调用标题优先使用可靠的显示元数据；Computer Use 的 cua_repl/js 从调用 arguments.title 提取标题，并在大参数/结果裁剪前保留，实时和历史路径一致。不从工具输出任意猜标题，无标题或陌生结构保留工具名回退。图像二进制不进入文本投影；长输出只显示分页片段，完整内容仍由原生历史保存，这与模型上下文传递无关。

初始任务的本地 action 在首轮启动结果确定后发出，使用该次 startTurn 返回的准确轮次 ID；早到完成事件清空当前 turnId 时也不会丢失关联。丢失启动回复时只接受该次缓冲区唯一观察到的启动轮次，未知则保留未绑定任务。前端只按来源、非空轮次和完整内容一一合并，不跨轮按正文去重。action 缓存不落盘，重新加载从原生历史恢复。协作前缀仅在展示副本开头精确剥离，并兼容上一版完整前缀；模型历史不改。

工具原始调用保留参数、输出和错误。状态行去掉普通成功/完成状态并合并重复阶段，保留耗时、退出码和异常状态；详情去掉已展示的工具身份、时间戳及成功标志。失败标志和未知业务字段仍保留，嵌套业务内容不作同名字段删除；没有有效详情就不创建空详情块。

通信正文由 `shared/communication.mjs` 从当前直接线程的原始 item 提取，先于通用预览裁剪：仅识别插件的无命名空间 `notify_parent` 和原生 `sendInput` / `sendMessage`，不按陌生 MCP 的同名工具猜测。活动条目携带最多 2,048 个 UTF-16 代码单元的正文预览；`ui_detail(view:'communication')` 在原线程内按准确轮次和条目 ID 读取完整正文，每页约 16,000 个代码单元，边界同步避开 Unicode 代理对。整段能放入单页时使用 Markdown，分页片段用普通文本保留换行，避免将残缺围栏或公式重新解释为富文本。通信详情独立缓存，失败保留已读页，收起或切换代理取消迟到的显示更新。参数与投递回执仍在原始调用中，发送失败保持可见；该投影不改变实际投递内容、事件确认或模型历史。

直接线程中的 `subAgentActivity` 和委派生命周期只投影子代理身份、图标与状态，不保留子代理指令和输出；明确的消息发送调用另显示当前直接代理自己发出的正文，不展开接收者的对话。名字可来自 `thread/started` 元数据，缓存有界；活动行另提供路径末段作为展示名，不会为了展示展开后代历史。等待工具有已记录的开始时间时按开始时间相对于后续事件定位；目标和时间缺失时不推断。历史分页与实时数据合并后也需应用这一规则。压缩状态来自 `item/started`、`item/completed`、`thread/compacted` 或历史记录的完成时间，未知阶段不冒充已完成。Desktop 压缩中采用灰色状态行与 SVG 的局部 SMIL 轻动效，不靠轮询重绘制造动画，完成后移除动画；终端使用静态文字。压缩只作用于对应线程，不禁用其后代或其他代理，压缩完成同时清理过期活动摘要。文件增删数在显示裁剪前由完整 diff 计算。

正文通过公开 Markdown 组件绘制。展示副本的数学片段扫描区分行内、块级、转义、已有美元分隔符及代码；仅转换完整 `\[...\]` 为独立行 `$$`，矩阵换行间距等 TeX 内部内容保持原样。`\(...\)` 原样交给宿主的行内解析器；该路径受宿主功能开关与启发式影响，不用单美元替换掩盖限制。原始 Codex 历史不变。工具结果用原生文本/边框组件；本机绝对路径 PNG 可按需使用 Image。CLI 公式和 Mermaid 保留可读源码。公开 Client 只输出受限组件树，不注入任意 DOM 或执行工具输出中的 HTML。

文件详情通过原生 item 中的确切路径选取，不把路径当文件系统读取参数。当前 Desktop 的 `Code({format:'diff'})` 只着色，不画行号表；完整单文件 unified diff 因此用公开 Box/Text 绘制旧、新行号和红绿底色，每段最多 120 行，右上角仅一个复制入口。未知或不完整格式保留原生 Code 源码视图，终端使用原生 diff/source。文件名只在外层展开标题显示，diff 内不重复标题，复制控件固定在内容右上角；真实路径仍用于正确选取详情。普通代码沿用 Code 的 language/path 和 Markdown 围栏语言，合法 JSON 传入 json，其余不猜语言。正文整体交给宿主 Markdown，标题、强调、列表、引用、表格、链接和带语言围栏无需逐类重写；Mermaid 使用宿主代码块特判，图片与链接遵循宿主 URL 检查。未知语言保留原文，未声明语言的工具输出保持纯文本。上下文指标来自原生 `tokenUsage.last.totalTokens` 与 `modelContextWindow`，不取 Claude session 用量，不做 tokenizer 估算。

后端实时投影按代理数、项数、字符、节点和深度限制；原生线程保留持久历史。一次历史请求目标为最近 30 个可见原生 item，不等于 30 轮：消息和工具记录分别计数，UI 折叠不改变计数。界面仅有一条连续时间线，历史向前插入，实时内容向后追加。已加载消息保留，往返已读区域不重新请求；合并后的时间线缓存复用，内容变化才重新整理。接近顶部时预取下一段，滚动回调不等待历史 RPC，真正到边缘才合并并恢复锚点，不显示加载转圈。

绘制窗口最多 500 项，同时服从整树 80,000 字符、12,000 节点、28 层深度预算，为宿主的 100,000 字符、20,000 节点、32 层上限留余量。预算从公开构造输入计数，不检查私有 DOM；超限围绕展开锚点或末尾收小连续窗口，滚动按实际窗口长度保留重叠，不能固定跳 250 条而跳过消息。单条超大记录的展示子树可分页查看，数据缓存和原生历史不变，复制回调保留完整原源；输入和导航控件保留。单条超大 Markdown/Code 分页使用等宽源码，避免破坏公式、围栏或 diff 语法；普通大小继续原生富文本。名称等外壳标签另有宽松的显示长度上限，原始名称、设置和动作 ID 不变；Input.value 遵循宿主独立字段预算，不计入整树文本预算。这个预算不参与模型上下文传递或压缩。

大工具详情按需加载、有界缓存，不预读全部原生历史。历史读取单次最多 80 次原生 RPC，跨请求只携带最近 64 个游标作循环检测，预算耗尽保留准确续读位置。UI 缓存保留最近 16 个代理，关闭环境后可从原生历史恢复。

打开面板时每秒查询变动，无变化不重绘，未打开不读详情。工具展开状态与消息合并独立，展开不冻结消息、进度或终态答复。上拉历史后用旧首项的稳定 key 保持阅读位置；用户后来滚动或切换代理会取消迟到的锚定。首次打开和直接发送后调用原生 `to:'end'` 跟随追加。展开立即退出末尾跟随并更新显示，`nearest` 定位请求不阻塞展开；已有输出立即呈现，缺失详情在点击返回后异步读取，缓存重开不重复请求。桥接每次并行读取当前会话和环境设置，避免六次串行宿主往返，不缓存可能变化的配置。发送撞上在途轮询时完成后跟进一次。异步响应核对代理与页面代数。所有 ui_* 内部请求不确认或消费 Claude 事件。

面板匹配包含具体 requestId；使用公开 state 订阅定向更新，避免活动更新令主线程工具行和其他面板一起重绘。稀疏模型状态更新只修改实际存在的字段，不清空 UI 专用权限和用量；显式 null 仍会清除旧值。渲染回调只读取状态，滚动恢复由导航动作触发。工具输入与输出按结构拆分，通过原生 Code 保留等宽和换行；延迟输出展开时请求 `ui_detail(view:'output')`，只有 `next_offset` 非空才提供下一页，原始调用单独折叠。元信息使用宿主 caption/footnote 字号。公开 Input 没有附件事件，Windows 选择文件与显式粘贴附件通过独立本机进程完成，剪贴板不被后台监视；附件显示名称有界、自动换行，真实路径不被缩短。

Desktop 使用公开 `e.props.scroll.bodyRows` 设置对话最小高度，中间消息区伸展，短对话的输入区仍在可用面板底部；长对话随宿主整体滚动。不读取私有 DOM，不重写宿主样式。输入区保持单层原生 Input。圆钮 Client 外壳与内部根 Box 均明确为 2lh，避免中间无固定高度容器使百分比高度失效；底栏按统一中心对齐。集成标题和子项采用相同间距，左侧细竖线仅是装饰，外层折线箭头可折叠整组，工具标签自身可展开输出。正文与工具组按侧栏密度排布。

分组折线箭头为原生 SVG；文字保留 Button，箭头用透明 Client 命中区域覆盖，指针与键盘事件仅切换当前代理的对应分组，过期状态点击不反转新状态。代理标记共享有界的稳定图形槽位，Desktop 使用多样 SVG，终端用对应字符；无目标的等待事件使用中性时钟图标。传入消息的 85% 限宽属于无边框外层，气泡自身自动宽度、右对齐，避免短句被撑满。

标题与折线箭头位于零间距内层行，前置工具图标保持外层间距；箭头命中区从左侧排 SVG，减少父容器间距、原生 Button 内边距和图形空白叠加。代理名在主会话入口、面板标题和子代理活动行统一将首字母大写，仅转换显示文本，动作始终使用原 ID。

“回到最新消息”仅在离开末尾时显示。公开 Pane 没有固定浮层槽；Desktop 居中圆形按钮按本次宿主滚动重询提供的 offset/bodyRows 定位，不另设滚动轮询或触发全会话重绘。点击后切回末尾绘制窗口并调用原生 to:end；终端保留文本入口。真实悬浮跟随与 0.2–0.3 秒体感目标仍需实际宿主验收，离线测试只证明无重复 I/O、滚动不等待未完成请求及有界构造。

## 缓存

父 Claude 的请求历史、系统提示词和工具描述均不被本插件重写。工具 schema 固定；ToolSearch 的生命周期交给宿主。读取当前可用快照是只读操作，Claude 的 cache_control 不作为正文复制。新 Codex 初始上下文有固定前置说明；后续保持同一线程并追加输入。

实际缓存读取和写入量来自 `thread/tokenUsage/updated`。压缩、模型切换、宿主升级和供应商缓存过期应与普通续接分组观察，不能用随机样例的一次命中替代验收。插件不发付费心跳维持缓存。

## 明确失败的边界

- 宿主不支持所需公开接口，或未返回合法消息数组。
- 无法无损映射的二进制附件、非法消息角色或非 JSON 工具证据。
- 超出传输硬限制的报文：JSON-RPC 帧 16 MiB、本机 HTTP 请求 64 MiB。它们是实际字节限制，不是模型上下文估算；不截断或擅自总结。
- 协议不支持、动作结果不明、过期审批、恢复仍超限、状态落盘失败。

这些边界会返回错误，不伪造成功、不静默改用 `none`，也不让模型代写昂贵的交接摘要。宿主正常的 4,096 条返回限制属于 `available` 的已声明语义，不被当作完整继承。

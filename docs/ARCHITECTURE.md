# 架构与边界

## 模块

`hooks/register.js` 是 Claude mod：注册九个按需工具，读取宿主公开接口提供的当前快照，等待重要事件并确认最终保留消息。`hooks/bridge.js` 仅提供静态导入的本机通信；UI 使用它不会进入模型交付确认流程。

`hooks/rows.js` 只改写工具调用和本插件通知的显示：不同代理图标与可点击名称组成简短生命周期记录，展开宿主完整记录时保留原始输出。`hooks/ui.js` 使用宿主公开的 Pane、文本、输入与展开组件呈现代理对话，提供 `/codex-agents` 键盘入口。`hooks/action-control.js` 仅绘制圆形发送／停止控件，经 `ui.message` 通知 hooks，hooks 再按当前选中代理、草稿和动作状态执行；没有模型工具或独立文本编辑器。`runtime/activity.mjs` 是独立只读投影，使用原生线程历史分页与有界实时缓存，不读写模型 pendingEvents。`shared/tool-output.mjs` 统一提取结果文本与有效结构化内容，跳过空协议占位；共享运行代码也纳入 helper 构建指纹。

`runtime/settings.mjs` 验证用户权限与活动名额，未知设置键拒绝。`runtime/roles.mjs` 读取唯一的经验指引源、保守判断原生 default fallback，并只读检查外部线程的首条 session_meta 动态工具元数据。角色 TOML 与完整审阅稿由 `scripts/guidance.mjs` 生成，检查脚本验证一致性。

`runtime/context.mjs` 是无状态转换器：校验消息格式，保留消息角色与顺序，跳过 thinking，把历史工具调用/结果转成不可执行证据，传递可表示媒体，生成稳定摘要。它既不读 JSONL，也不合并之前的快照。仅移除缓存控制字段等传输元数据，普通工具参数中同名字段保留。

`runtime/appserver-client.mjs` 负责 JSON-RPC stdio，包括初始化、反向请求、超时、分帧、背压、错误和关闭。`runtime/agents.mjs` 负责线程状态、审批、消息、续接和超限恢复。

`runtime/bridge.mjs` 和 `runtime/broker.mjs` 为每个 Claude 会话提供一个本机桥接进程。控制请求使用 Node 原生 HTTP 和会话鉴权令牌，状态目录按 session ID 哈希隔离。继承的消息由 `$.session.messages` 导出，再由 `$.http.fetch` 发往仅监听 `127.0.0.1` 的 broker。进程标准输入只承载派发指令和本次传输的凭据。临时凭据只准写入该次调用的快照，收齐后消费一次；传输中断时不会启动缺少历史的代理。

新建代理时，显式选择的推理档位同时进入 `thread/start.config.model_reasoning_effort` 和 `turn/start.effort`。登记记录保留此选择，以便恢复原线程时继续采用。创建请求省略档位的普通代理、以及没有选择来源记录的旧线程，沿用 Codex 返回的原生档位。

未匹配当前登记的裸 UUID 才进入原生线程查询。该查询失败时，错误仅说明当前登记未匹配及原生读取失败，保留底层原因，并提示当前 `list_agents` 或原始 `thread_id`/链接；不从 RPC 错误码推断 Claude 分支、跨会话来源或历史丢失。显式线程链接的读取失败只给出线程检查指引；线程状态拒绝和登记后的发送失败保持各自诊断。此提示不会扫描其他会话、转换目标或额外发起模型请求。

`runtime/delivery.mjs` 管理单批交付租约、正文校验和精确确认；`hooks/delivery.js` 仅从宿主最终保留消息中识别本插件交付，兼容裸信封及 Claude 为本插件添加的两种精确固定包装（轮间、轮内）。不扫描任意嵌套 JSON；回执仍核对交付 ID 和完整事件内容。主界面通知行复用同一解析器。`runtime/receipts.mjs` 用单个动作对应单个原子文件保存回执，启动时迁移旧 `receipts.json`，不全量加载已有回执。

## 代理目录入口

桌面 `SessionMode` 组合 `next(e)` 和纯文本 Codex 按钮，使用宿主输入区下方的紧凑槽；桌面 AbovePrompt 原样透传，不再产生全宽灰条。终端仍用 AbovePrompt，调查问卷期间让位。计数和开关状态读取独立 `entryRevision`，仅成功写入 state 后确认签名，失败可重试；对话仍只订阅 `paneRevision`。开关串行执行并以 `$.ui.panes()` 为准，关闭保留缓存及草稿、停止 UI 轮询，不暂停模型。

非 wait 模型工具的桥接请求携带 `ui_summary:true`，broker 在动作/回执之后附上当前活动摘要；不将此摘要写入幂等回执，重放动作仍附最新列表。hooks 先更新 UI，再剥离摘要返回模型，无额外桥接往返。通知观察用 activity epoch 防止旧 offline 响应关闭新的观察，以及旧快照覆盖新列表。UI 与事件领取/确认依旧分离。

`hooks/agent-directory.js` 负责纯分组、排序、相对时间、Unicode 名称截断及公开组件布局。只展示当前 Claude 会话直接登记、未清理的代理；终态放在「完成」，未知状态明确标注，归入「已开启」。两组独立每页 50 条，目录仅请求摘要，不加载所有代理的历史。目录刷新单请求在途，无变化不重绘；旧响应不能覆盖新选择。返回列表时保留目录的页码和滚动位置，以及各代理的草稿和已读历史缓存。再次点进代理时定位到输入框。顶部和输入区均提供返回列表。

目录的「暂停全部 Codex」使用原生按钮和行内确认。可暂停或停止未确认的代理存在时才提供操作，空闲代理也可暂停。确认后走同一个 `ui_interrupt_all` 调用，在途时隐藏重复提交入口。目录显示批量结果并刷新摘要。

控制器持久保存 `createdAtMs` / `lastActivityAtMs` / `threadName`。显式委派名称优先，否则 UI 使用原生 Thread.name，不能用包含首条任务正文的数据库 title。缺失元数据在目录读取后后台补齐：只读 `thread/read(includeTurns:false)` 和最新 `thread/turns/list(itemsView:notLoaded)`，Unix 秒转毫秒；最后活动优先最近轮次 startedAt，回退 Thread.updatedAt。最多 4 项并发、单请求 800ms、失败 30 秒退避；关闭或替换后忽略迟到结果，不覆盖期间新活动。不会通过元数据查询启动/恢复模型轮次，也不把查看时间冒充活动。UI 只输出时间展示字段，模型 `list_agents` 契约不变。

代理导航在每个 await 后核验同一 generation，不在旧请求结束时认领新请求的代数。切换开始即撤下旧内容；尚可见的旧目录项点击仍可替换待打开目标。历史边缘的新非零人手势在冷却后可重试，不要求离开三行；在途请求和自动短页填充闩锁仍保留，零位移布局不能取消正在加载的导航。窗口规划和位置补偿算法未重写。

## 初始历史

新建代理在注入历史和启动首轮前校验所选模型。能从项目配置确定供应商时提前读取其可见目录。原生线程返回另一供应商时按实际供应商复查；明确指定的型号与解析结果不一致时返回两者，任务尚未派发。

顺序固定为 `thread/start` → `thread/inject_items` → `turn/start`。只在新线程注入一次。没有使用内部专用的 `thread/resume.history`，也没有借用会遍历整个源文件、截短工具内容的外部会话导入器。

直接使用宿主原有 `session.messages({as:'api'})`，不修改 Claude 安装。参数命名为 `context_mode: available`，含义是接口当前可用的窗口，不能声称完整生命周期历史。已核验内核最多取最近 4,096 条正规化消息，再移动到合适的用户消息边界；实际返回可能更少。原始记录数、响应数组短小或 token 估算均不被当成完整性证据。

例如内部 poll 事件和附件可以展开为多条 API 消息。插件不尝试猜测遗漏程度，也不将返回结果与磁盘旧日志拼接；初始说明会告知 Codex 这一范围，缺少必要信息时由 Codex 问 Claude。快照统计只报告实际返回和传递的数量，不报告虚构的总历史数或完整率。

范围预览从已经转换的历史投影首尾，排除固定说明和 thinking。每端最多 160 Unicode 字符，媒体仅类型占位，工具参数与证据信封不回流。预览不参与历史 digest，也不改变注入内容；只随 spawn 的响应及其幂等回执保存，不加入代理状态记录或日常 list 响应。

`contextSource` 在新建或外部采用时确定并持久化，投影为 `context_source`：none 为 new，available 为 claude，外部原生线程为 codex。续接不改来源。旧状态只依据明确的注入快照或外部线程标记迁移，否则为 unknown；不把缺少证据当作全新线程。

模型上下文与展示历史分别使用原生接口。Codex 0.169.0 的隔离离线探针验证 `thread/inject_items` 的继承消息不会进入 `thread/turns/list` / `thread/items/list`，因此不另按正文、首轮或条数隐藏消息；两轮实际任务及中间压缩记录仍可读取。外部采用不注入 Claude 快照，侧栏保留其原生展示历史。分页跨压缩记录继续，不把模型压缩边界当成历史终点。

## 协作

父代理事件与侧栏活动分离。`compacting`/`compacted` 是仅供展示的状态：不写入父代理通知 journal；`parentDeliveryEvents` 在启动恢复及领取时也排除旧版遗留项，原有领取逻辑确认清理排除的 seq，旧的纯压缩租约不会堵住后续结果。ActivityStore 继续直接处理原生 contextCompaction 事件，状态、活跃工作判断及压缩失败恢复保持不变。问题、审批、真实失败与完成仍照常交付；陌生业务事件不因这个过滤而丢弃。

运行中消息使用 `turn/steer` 及 `expectedTurnId`，向当前任务加入指导，不调用停止。空闲消息通过 `thread/inject_items` 写入邮箱，返回 `stored`，但不启动推理；`followup_task` 才在原线程开新轮。判断依据是消息到达时的代理状态，不对测试消息或正文做语义分类。待回答问题或审批必须走 `answer_agent`，不通过 steering 绕过。

若指导的确认晚于目标轮次结束，`steer_unconfirmed` 表示该轮是否用到这条消息仍待核实。侧栏保留草稿与附件，维持代理的真实状态。重复读取同一次明确的入参校验失败会得到原错误。原生调用已发出却丢失确认时，保留结果未确认的回执。

原线程的模型缺失或被供应商明确拒绝时，控制器登记本次故障。首次从深链接接入时先登记线程，预检失败也保留代理 ID。成功读取该线程供应商的目录时，`available_models` 包含完整可见 ID，包括可见但被上游拒绝的型号。`recovery_choices` 只包含当前可选的型号与对应的签名 `target`。`recommended_model` 最多返回一项，要求模型家族和完整后缀匹配，版本严格高于原型号，并在合格项中取最高版本。有候选但无推荐时，Claude 请尚未选定型号的用户选择。目录读取失败时省略目录和候选字段，成功读取时用空数组区分空目录与有可见型号但无可选项。原模型与这次恢复中已被上游拒绝的候选从常规选项中排除。仍可见的被拒绝型号另列在 `retry_after_access_fix`，采用独立签名，供用户确认访问已恢复或已修复经核实的兼容性问题后重试。

Claude 将选中的目标和原任务交给 `followup_task`，普通续接和恢复共用 `target`、`message` 两个参数。重试先核查代理状态及目录。故障仅由目录缺失引起且替换尚未完成时，重试发现原模型恢复可见才解除该次故障。原生轮次确认接收替换模型后，代理保留原线程和选中的模型，旧模型再次可见不触发切回或后台通知。后续提交同批已用目标时，返回已接收的模型和轮次，本次不派发。无法识别目标时，提示用 `list_agents` 显式只读核查。用户暂停、待处理请求及活动后代继续约束发送。

候选的启动请求发出前登记候选模型、推理档位和此前最近的轮次 ID。若回执丢失，可依据原生模型及新轮次核实是否已接收；证据不足时保留未知状态，防止重复发送同一任务。报告已创建的轮次只说明原生接口观察到该轮次；费用和输出由供应商及实际执行决定。

用户直接操作使用内部 `ui_send` / `ui_interrupt`，共享认证、动作回执和幂等检查。用户消息带固定来源前缀，活动投影显示为用户消息；运行中 steering，空闲时在原线程开启下一轮。私人用户消息正文和独立用户轮次的自动完成、失败、压缩等结果留在 Codex。每轮 `turnOrigin` 持久化，显式协作、问题和审批仍可交付。用户指导运行中的父级轮次保留其归属。启动迁移排除精确旧 send 回执及同 agent/turn 的自动结果。暂停进度由侧栏状态呈现，父级只收到操作结果。普通 UI 轮询不产生事件。

用户直接对话后，同一 Codex 线程及其完整原生历史继续可用。Claude 的 `followup_task` 可指导活跃的独立用户轮次，只有原生接口确认同一轮接受时才转交父级归属；请求与完成交错时结果可能未确认，迟到回执不得覆盖归属。用户轮次完成后，后续任务可在同一线程开启父级新轮次。`wait_agent` 只等待父级工作或待回答请求；`parent_idle` 与 `active` 配合区分私人活动和真正空闲，helper 的存活与名额仍统计全部工作。

私有轮次中的显式 `notify_parent` 仍是协作事件。Claude 空闲且宿主会话存活时，后台观察领取事件后通过 `prompt.submit` 提交，宿主可开始新的 Claude 轮次。观察周期为 10 秒，主轮正常结束也触发检查。主轮工具链继续时，插件在 `turn.step` 产生工具调用的响应结束后，或 `session.append{door:'tool-result'}` 保留工具结果后，领取事件并以公开 `session.append` 追加 user-role 注记。响应请求 `wait_agent` 时将事件留给等待工具。工具结果路径先确认属于本插件 `wait_agent` 的已保留事件，再尝试领取其他事件。两个入口都捕获原主轮 ID，异步返回后核对当前轮和取消信号。

原生模型请求先选取消息并合并 arrived rows，再进入 `turn.step`。插件把忙碌时的投递放在下一步骤选取输入前的工具链边界。仅含最终答复的响应留到空闲观察交付原结果。下一 `turn.step` 进入时清除待处理标记。如果轮次先正常结束，优先用下一批实际事件启动请求。只有当前没有新批次，且已保留的问题或审批仍阻塞同一 `agent_id` 和 `request_id`，才可提交一次提示。用户取消后，自动投递和补充提示等到用户开启下一主轮。崩溃后依据宿主恢复的窗口补确认，确认代表消息已留存。

等待与通知沿用同一交付租约：正在等待时不另领取，异步领取后复查并发等待、代理关闭及主轮变化。追加以实际保留内容核对事件再确认，拒绝、改写或失败释放未交付事件；确认失败保留恢复证据。已通过 `wait_agent` 确认的结果不重复追加。Codex 已完成后须先由用户侧栏消息等操作启动活动轮次，才能调用 `notify_parent`；未运行的模型不会自行发送。这里沿用现有 Claude 会话与宿主调度，不另开 Claude API 客户端。

原生 `cc-plugin-sec-default` 启用时会将 `classic.*` 转发越过个人插件，旧 `PostToolBatch` 路径因而不可用；rc.22 已删除该注册。安全模块允许这里使用的 `turn.step`、tool-result 和插件自身 note 路径，所有上层拒绝仍照常生效。不改安全策略，也不注册广泛的 `tool.call` 观察器：宿主会因这种工具钩子关闭对应工具的可分离执行。

附件只由用户界面提交路径；后端校验本地普通文件、识别图片格式后，将图片转换成原生 `localImage`，普通文件以明确路径交给同一工作环境的 Codex。没有假设 `mention` 支持任意文件上传，也不向 Claude 传文件内容。文件校验前取得控制轮次标记，校验期间发生停止则取消发送。附件元数据与用户正文保存在原生历史中，活动投影恢复文件名及来源。选择器仅响应用户点击，Windows helper 用固定 PowerShell 代码，目录通过环境变量传入；不支持系统选择器时输入路径。

用户停止先持久化暂停意图，再中断该根及已知后代；新到的后代关联和启动事件也受停止约束。只有原生结束事件或元数据确认才解除活动占用并报告已停止；断线及不明状态保留未确认。暂停的原生线程 ID 跨关闭登记保留，重新采用也不会自动开工。用户恢复的独占标记阻止 Claude 的消息、续接与回答穿过恢复窗口；恢复成功前保留持久暂停标记，失败或结果不明时重新停止。关闭 UI 或取消等待不改变执行状态。

`/codex-stop` 通过 `command.register({immediate:true})` 与 `command.run` 直接调用内部 `ui_interrupt_all`。批量暂停固定当前会话的已登记根代理名单，涵盖空闲和已完成的代理。先同步设置全部暂停屏障并共同等待持久化，再并发暂停各自子树。事务期间拒绝新建和用户恢复，跨事务的未登记接管用 epoch 拒绝。单个树的失败由该树状态反映，其他树继续处理。逐项结果供 UI 使用；对 Claude 交付时只发一条会话级结果，无 `agent_id`。每个操作经过同一用户动作回执与幂等路由。无 endpoint 或服务锁时返回离线；已有但不可达或不兼容时保留未知状态。

暂停操作与对应 `user_action_receipt` 在同一日志中持久化。各代理树的停止都确认后发布一条 `phase: "confirmed"`。原生失败或 10 秒确认窗口到期且树仍活动时，唯一结果为 `phase: "unconfirmed"`。批量结果以 `unconfirmed_agents` 给出尚未确认的范围。迟到确认更新侧栏状态。批量操作有新增的活跃暂停目标才发布结果，此结果纳入所有仍活动的目标及重叠的未完成单项暂停。暂停覆盖的轮次仍在原生历史记录中，关联的常规父级 `interrupted` 由该操作结果代替。

直接代理以 thread ID 索引。合法后代由 `parentThreadId` / `source.subAgent.thread_spawn.parent_thread_id` 关联。后代工具、推理、usage 和最终结果不传播；问题和审批保留源线程 ID，通过原始 JSON-RPC ID 回答。外部请求 ID 统一为字符串，内部仍保留原类型，避免数字 0 的丢失。

原生 `request_user_input` 在默认工作模式启用，用于必须得到回答才能继续的事项；简短 `notify_parent` 动态工具用于重要协调，不播报常规进度。重要设计问题、实质分歧或更优方案应在大量实施前沟通，不强制每项任务先讨论一轮。工程、验证和交付规范由适用的 AGENTS.md 等原生指引提供，协作提示不重复注入。Codex 自己的多代理能力保留。

`request_user_input` 保持原始服务端请求待答，代理进入 waiting，由 `answer_agent` 使用准确请求 ID 和响应结构解除等待。`notify_parent` 返回投递确认即结束该工具调用，不具有这一等待语义。协作指引明确两者区别，不依靠通知内容猜测是否需要重新启动已完成的代理。

`role: default` 使用配置的 Luna medium，hook 与 broker 在读取快照前将上下文模式归为 none，显式冲突则拒绝。该角色关闭原生子代理、生图和主动提问工具，角色职责要求只读、单轮、一次最终交付；其他角色不受这些开关影响。

直接活动任务默认最多 5 个（用户可设 1–7）。控制器在第一段异步操作前同步预留容量；starting、running、waiting、compacting、unknown、正在续接和有活动后代的根任务保守计数。完成、失败和停止且无其他活动的登记不占名额。宿主重启后先核实不明任务的原生状态，不能仅因重启就假定名额已释放。

权限由用户配置注入 helper，不在模型工具 schema 内。full-access 使用 danger-full-access/never；auto-review 与 ask 使用 workspace-write/on-request，分别采用 auto_review 与 user 审批者。新建和续接都应用相同设置；runtime 指纹包含设置与指引，不匹配的 helper 不会被静默复用。

## 等待与交付

工具调用内的程序长轮询每 25 秒续订一次，模型只收到实际等待结果。后台观察用于续租和 UI 更新。检测到排队事件且可领取自动通知时，broker 用 250 毫秒收集相邻事件，再按同一批交付。等待工具和只读 UI 请求直接获取已有数据。

同一未领取批次内，普通 `notify_parent` 文本与同代理、同原生轮次的最终答复逐字相同，保留终态并退役较早的文本。附带业务字段的消息、独立问题、其他轮次和其他代理保留。用户暂停时撤下尚未投递且已经无法回答的问答及审批。

后代轮次或已报告终态的根轮次发生结束状态变化后，在持久化完成时发内部 state 唤醒；不生成额外 Claude 消息，也不增加轮询。wait 在空 claim 后、返回 idle 前重新检查事件队列，防止完成事件恰好在空租约保存期间到达而被首轮漏报。其余后代或请求仍占用时继续等待，不把根的最终文字当成整棵任务树已停止。

显式 `timeout_ms` 使用宿主侧等待截止时间，每次本地订阅最多等待剩余时长；到期只返回 `timed_out`，不调用 `turn/interrupt`。已有事件优先交付，零时限可以读取已到达事件。默认省略时持续等待。

内部事件有单调序号。归属单个代理的事件还有代理 ID、名称和轮次 ID；会话级暂停事件由其作用域和序号标识。broker 在返回前确认原事件日志已保存，按投影后的事件数组 JSON 大小分批，每批预算 128 KiB。超过预算的单条事件独立完整交付。wait 与后台提示共用持久交付记录及租约。并发 wait 返回已有等待者状态，避免同一工具组互相等待。提示排队期间续租，取消或拒收只释放租约。

异步模型故障缺少目录时，`wait_agent` 和实际提示交付在领取该事件时尽力读取供应商目录。读取使用有界等待，超时或失败照常交付原故障；补齐只作用于该次交付的投影和哈希。异步读取期间再次核查故障归属及事件是否仍待交付。显式调用 `list_agents` 会为待恢复代理只读刷新诊断与选项。历史错误保留失败原因和轮次状态，恢复目标只出现在本次诊断中。后台观察的状态摘要和普通等待状态检查不做目录刷新。

模型可见的 v1 交付投影移除顶层原生 turn/thread/item 路由 ID；保留代理名称、可操作的 agent/request ID、序号、类别及完整业务内容，未知业务字段和嵌套内容不删。模型失败反馈的正文保留已经观测到的轮次 ID。新批次按实际投影内容计算确认 hash，旧批次仍核对旧原文，journal 不改写。Claude 为后台 prompt 加的英文框架来自宿主，插件不修改它；投影同时适用于 wait 和后台通知。

`session.append` 的 `await next(e)` 成功返回后，以最终保留消息为依据确认准确序列，不能仅凭工具返回、最大游标或 prompt receipt 删除事件。只读工具结果须匹配完整工具名和 tool_use_id；恢复时只扫描一次当前宿主 API 窗口。交付 ID 在当前会话的目录内查证，事件正文以 canonical hash 比对，部分保留只确认对应事件。0.1.1 的旧结果也必须与 journal 中完整事件相等。helper 离线或确认失败时保留证据，随下一次有效操作先补确认。

同一次 `spawn_agent` 或 `followup_task` 已在同步结果中报告的启动失败，后台事件最多暂缓 5 秒，等待宿主保留工具结果。按 `tool_use_id` 和精确结果核对动作回执，再确认对应原事件。工具结果未保留时，该事件仍可由 `wait_agent` 或自动通知交付；其他事件照常领取。

确认订阅 `tool-result` 与 `prompt` 两类追加事件，依据工具来源识别本插件结果。内置安全插件跳过的 attachment、hook-context、compaction 等受保护事件与本插件确认无关。

公开宿主 API 的确认点是消息进入当前 conversation；恢复扫描依据宿主已经恢复的窗口。宿主与插件并无跨存储事务。异常中断下，无法确认的交付保留原 seq 重投，不静默丢弃；这不会重派模型任务。动作回执在副作用前落盘，按工具调用 ID 和输入指纹拒绝重复派发或 ID 混用；结果不明不自动重试。

## 恢复

普通超限错误不能被假定为会自动恢复。控制器等待失败轮结束，最多调用一次 `thread/compact/start`；确认压缩完成及其轮次结束后，只追加继续指令，不重新发送长任务或重注入快照。再次超限或压缩失败明确结束。父线程中断优先于恢复。

本机控制器重启后，曾运行的任务先标为状态不明，过期问题 ID 清除；查询原生元数据确认状态，显式 followup 才启动新轮。桥接关闭会清理客户端子进程。约 90 秒的租约代表宿主仍存活，由等待和后台观察续租；宿主失联时清理所属工作，不以原生任务活动替宿主无限续命。它只管理本插件的进程，不停止用户其他 Codex 会话。

turn/start 的明确 RPC 拒绝产生本代理 failed；没有启动证据的传输异常产生 unknown。若已观察到有效启动或完成，则保留真实状态。unknown 的显式操作先用 thread/read(includeTurns:false) 查询：idle/notLoaded 可恢复；active 必要时 resume(excludeTurns:true) 建立订阅，再读取最新一条无 items 的 turn。未确定状态前不自动重放任务。审批只能选择该请求 availableDecisions 提供的决策。

启动和服务锁使用 PID 与随机 owner token，锁内再次核验 endpoint；helper 在建立 Codex 连接前取得整个生命周期的服务锁。Windows 在释放锁期间可能短暂拒绝读取目录。遇到 `EPERM` 时先重读，持续失败则返回原始权限错误。活 PID 不按文件年龄抢占。构建不一致时，仅同协议且声明 `idle_shutdown` 能力的 helper 可以自动更换：旧 helper 在同一个同步检查中确认没有活动工作和其他在途请求，并封闭新操作准入；调用方等待 endpoint 和服务锁都释放后启动新版本。活动任务、协议不兼容或旧 helper 未提供该能力时明确报错，不强行停止。连接关闭监听先于初始化，health 反映实际状态；休眠或长事件循环暂停后留续租宽限。上述升级保护不改变宿主失联租约的清理语义。

状态写入按微任务批合并，同一批调用共同等待保存结果；普通代理错误局部处理，真实持久化失败统一停止 helper。按当前任务/轮次管理去重集合，已回答、已过期和不可恢复的请求事件不继续交付。必要的动作 ID、关闭线程 ID 继续保留，以避免重复执行和迟到事件重新关联。

`close_agent` 只移除无活动轮次、待处理请求、并发操作和活动后代的终态代理。卸订阅后再次校验，清理本地所有权与待交付事件，保留原生历史；持久化已关闭线程 ID，避免迟到事件使记录复活。它不删除工作文件或 Codex 历史。

批量关闭先解析选择器并固定代理集合；except 仅用于 all，活动项逐项跳过。内部关闭 ID 列表用于 hook 过滤迟到交付，模型只收到数量和例外。卸订阅后若因新活动拒绝关闭，必须恢复订阅；恢复失败保留未加载/不明状态和可操作错误，不能伪装仍在收取事件。

外部续接支持原生 UUID 或 codex 深链接，按原生 cwd 与历史登记，不再注入 Claude 上下文。同一目标的首次登记串行，活跃/不明外部线程拒绝接入。0.169 不允许在 resume/fork 替换原客户端动态工具，接入结果明确报告这一限制；不支持的旧工具调用返回解释，并按工具去重发出注意事件，不自动重派任务。

同连接的已加载代理直接开始下一轮；重启或卸载后才恢复线程。已完成状态不代表原生 writer 已释放。RPC 错误保留方法、错误码及已识别的安全诊断（writer 占用、归档、缺少历史和先恢复原生父代理），不透传任意错误 payload。writer 冲突不自动抢占、删除锁、重放任务或建立替代线程。

## 显示边界

Claude 主会话中，`list_agents` 的折叠工具行只显示本次查询的代理数量，点击可打开代理列表。展开工具调用可查看查询返回的各代理状态。只有实际收到完成事件时，等待结果或通知才显示「代理名 已完成」。

仅直接代理的事件进入活动投影；推理正文不展示，后代细节不递归读取。消息、工具、命令、文件修改及图片文件信息按类型格式化。调用标题优先使用可靠的显示元数据；Computer Use 的 cua_repl/js 从调用 arguments.title 提取标题，并在大参数/结果裁剪前保留，实时和历史路径一致。不从工具输出任意猜标题，无标题或陌生结构保留工具名回退。图像二进制不进入文本投影；长输出只显示分页片段，完整内容仍由原生历史保存，这与模型上下文传递无关。

初始任务的本地 action 在首轮启动结果确定后发出，使用该次 startTurn 返回的准确轮次 ID；早到完成事件清空当前 turnId 时也不会丢失关联。丢失启动回复时只接受该次缓冲区唯一观察到的启动轮次，未知则保留未绑定任务。前端只按来源、非空轮次和完整内容一一合并，不跨轮按正文去重。action 缓存不落盘，重新加载从原生历史恢复。协作前缀仅在展示副本开头精确剥离，并兼容上一版完整前缀；模型历史不改。

工具原始调用保留参数、输出和错误。状态行去掉普通成功/完成状态并合并重复阶段，保留耗时、退出码和异常状态；详情去掉已展示的工具身份、时间戳及成功标志。失败标志和未知业务字段仍保留，嵌套业务内容不作同名字段删除；没有有效详情就不创建空详情块。

输入消息只按明确的动作来源或原生文本中的既有通信前缀分类：直接消息显示 User，已识别的父任务显示 Claude，无法确定来源的旧原生 userMessage 显示“消息”。不按整轮最后的发送者推断每条消息，不为显示额外复制历史动作。

插件自绘复制入口共享 `copyWithFeedback`：点击立即进入待确认态，仅 `ui.copy` 返回 `isCopied:true` 才显示勾号及短暂成功提示；拒绝、异常和未知结果显示失败，切换代理和更新的复制意图使旧回调失效。差异复制保持原始补丁和 CRLF。原生 Code/Markdown 的内建复制由宿主自行处理，公开组件没有替换其内部按钮的属性；只读 Desktop 叶子组件确认其使用 `didCopy` 切换 Check 图标，插件不叠加重复按钮。

通信正文由 `shared/communication.mjs` 从当前直接线程的原始 item 提取，先于通用预览裁剪：仅识别插件的无命名空间 `notify_parent` 和原生 `sendInput` / `sendMessage`，不按陌生 MCP 的同名工具猜测。长消息和通信正文一次展开全文并可收起；不超过 48,000 个 UTF-16 代码单元时完整使用原生 Markdown，超限时一次返回安全预览和完整临时 Markdown 文件链接。重开复用缓存，不提供继续展开按钮。参数与投递回执仍在原始调用中，发送失败保持可见；该投影不改变实际投递内容、事件确认或模型历史。

超限正文的完整 Markdown 临时快照不截断原始内容、不接受外部文件路径。快照和媒体文件使用同一串行缓存：活动存储存活期间不淘汰已返回的文件，最多 512 个文件、256 MiB；达到容量时明确拒绝新增文件，已有链接保持有效，活动存储关闭时清理。转换时另有至多一组临时输入与输出，异常后清理；外部删除的缓存文件可重新生成。最终答复的 `phase` 与截断标记在预览裁剪前保留：仅原生 `final_answer` 且有完成证据时提供复制，不再猜测 phase 未知的旧记录，commentary 和 partial_answer 不冒充最终答复。复制通过 `ui_detail(view:'message')` 读取完整原文，与界面展示片段无关；复制专用 `bulk:true` 每批最多 524,288 个代码单元，预留宿主进程 stdout 的 4 MiB 限额。前端检查游标推进、总量上限、当前代理与复制意图，并处理 `isCopied:false`，不伪报复制成功。

直接线程中的 `subAgentActivity` 和委派生命周期只投影子代理身份、图标与状态，不保留子代理指令和输出；明确的消息发送调用另显示当前直接代理自己发出的正文，不展开接收者的对话。名字可来自 `thread/started` 元数据，缓存有界；活动行另提供路径末段作为展示名，不会为了展示展开后代历史。等待工具有已记录的开始时间时按开始时间相对于后续事件定位；目标和时间缺失时不推断。历史分页与实时数据合并后也需应用这一规则。压缩状态来自 `item/started`、`item/completed`、`thread/compacted` 或历史记录的完成时间，未知阶段不冒充已完成。Desktop 压缩中采用灰色状态行与 SVG 的局部 SMIL 轻动效，不靠轮询重绘制造动画，完成后移除动画；终端使用静态文字。压缩只作用于对应线程，不禁用其后代或其他代理，压缩完成同时清理过期活动摘要。文件增删数在显示裁剪前由完整 diff 计算。

所有正文（包括 Claude 和直接用户消息）通过公开原生 Markdown 组件绘制。`hooks/message-markdown.js` 仅在展示副本保守修复中文粗体闭合，并保护代码、数学与链接；原始历史和复制不变。数学片段扫描区分行内、块级、转义、已有美元分隔符及代码；仅转换完整 `\[...\]` 为独立行 `$$`，TeX 内部内容保持原样。`\(...\)` 原样交给宿主的行内解析器，该路径受宿主功能开关与启发式影响。CLI 公式和 Mermaid 保留可读源码。公开 Client 只输出受限组件树，不注入任意 DOM 或执行工具输出中的 HTML。

工具图片仅在对应工具展开后通过 `ui_detail(view:'media')` 按需读取；已完整投影的纯文本结果不额外读取媒体，延迟条目仍检查媒体。Client 只发送动作 ID，不发送任意路径，切换代理清除预览；拖动超过阈值不触发放大。PNG 使用原生图片组件，多图横排换行；缩略图可在同一 Pane 放大，右上角 × 返回原工具位置。待发送 PNG 剪贴板图片和已发送 PNG 附件也可预览。Windows 上 JPEG、GIF、BMP 按需串行转换为 PNG，GIF 标注首帧，原图保留；WebP 等无法解码时保留原图链接。每批最多 8 张，原图限 10 MiB、边长 16,384、40M 像素；非 PNG 转换最长 15 秒、输出最长边 1,280。媒体扫描限 4,096 节点和 256 张图，超限返回明确提示和已识别数量下界。超限或异常时保留原图链接；没有可用原图路径的内嵌内容明确提示无法预览。原生工具文字不包含 base64 墙，混合输出仍保留文字。rc.15 中的回退在原生事件图片数据截断时，读取已登记线程的 rollout，按线程、轮次与调用 ID 精确匹配完整 `function_call_output`；验证 session 元数据后才使用结果。读取器只缓存文件偏移，不缓存媒体内容：线程和调用索引分别最多 32 和 2,048 项，单次扫描最多 256 MiB、单行最多 32 MiB，不载入整个文件。文件替换或缩短会重置索引；读取不到完整内容时保留明确提示。

文件详情通过原生 item 中的确切路径选取，不把路径当文件系统读取参数。`shared/file-changes.mjs` 统一处理数组和旧路径映射记录：add/delete 的 diff/content 是整份正文，按操作类型构成单向差异；update 使用 diff/unified_diff。此语义对应 [app-server 的生产映射](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/item_builders.rs)。创建、删除直接按正文行数统计，更新只统计完整有效的 hunk；缺失或未知数据不填造零行统计。重命名尾注只在确切 move_path 匹配时剥离，标题保留新旧文件名。普通命令或陌生 MCP 输出没有结构化文件变更时仍保留原输出，不根据工具名称猜测 Diff。

当前 Desktop 的 `Code({format:'diff'})` 只着色，不画行号表；因此用公开 Box/Text 绘制单列行号和红绿底色：删除取旧行号，其余取新行号；隐藏 hunk 标题和补丁前缀，仅在第一片移除前缀，正文原有加减号及续片字符保留。大型文件差异投影成每片最多 24 行、4,000 个 UTF-16 代码单元的虚拟历史条目，纳入连续窗口；超长单行可分片，代理对不被拆开，续片不虚构新行号。传输页缓存并预取两页，无需文件内容的上一页、下一页或内容分页器。未知或不完整格式保留原生 Code 源码视图，终端同样使用连续差异片段。文件缓存独立于普通工具详情，关闭的旧文件可淘汰，正在阅读的文件不会因其他工具输出而被清除。同步 Box/Text 差异窗口在连续两次几何采样稳定后可提前提交位置；含异步富文本的窗口仍使用原有稳定等待。文件名只在外层展开标题显示，右上角单一复制入口收集完整原始差异。普通工具输出仍可分页。普通代码沿用 Code 的 language/path 和 Markdown 围栏语言，合法 JSON 传入 json，其余不猜语言。正文整体交给宿主 Markdown，标题、强调、列表、引用、表格、链接和带语言围栏无需逐类重写；Mermaid 使用宿主代码块特判，图片与链接遵循宿主 URL 检查。未知语言保留原文，未声明语言的工具输出保持纯文本。上下文指标来自原生 `tokenUsage.last.totalTokens` 与 `modelContextWindow`，不取 Claude session 用量，不做 tokenizer 估算。

Diff 行与行号栏均显式使用 `alignItems:'flex-start'`。宿主会把未指定对齐方式的 row 内 Text 垂直居中；避免让长行换行后的行号落到正文中间。行号对应源文件行，不随视觉折行增加，空白源行仍保留自己的号码和行高。

后端实时投影按代理数、项数、字符、节点和深度限制；原生线程保留持久历史。历史以可见原生 item 为记录单位，不等于对话轮数。界面使用连续时间线，历史向前插入，实时内容向后追加；已加载数据缓存与历史预取分离，往返已读区域不重新请求。滚轮回调不等待历史 I/O；接近边缘时预取，真正等待时显示加载圈。

显示窗口由独立 `history-window.js` 按实际构造成本选择连续分组，整树服从 80,000 字符、12,000 节点和 28 层深度预算，并计入输入区、导航、分页器等外壳及 512 字符余量。候选至多 400 个原始 item，只惰性构造选中组和首个被拒绝的边界，每组每轮至多构建一次，不再整函数递归二分。空间不足时从相反侧先裁剪，保留靠近阅读端约 36k 字符、3,500 节点或至多 200 项，再独立补入预算允许的相邻内容；空间足够则直接添加。添加事务硬保留旧范围，普通展开优先保留点击锚点。既有分组边界沿用，避免新增调用合并到正在阅读的工具组。

顺序预取两批历史，UI 请求 `limit:400, character_budget:64000`。后端按投影 JSON 字符累计，在完整原生页边界停止，故最多多出一个原生页；每个原生请求最多 50 项，80 RPC 上限与准确游标保留。未指定字符预算时仍为原默认 30、上限 50。读取批次是缓存数据，显示量另由实际渲染树决定；预取不改变当前视图。每组仍按 32k 字符/4k 节点/22 层分页，过大保留范围复用已构造内容页缩小表示，完整原文不变。预算不参与模型上下文传递或压缩。

大工具详情按需加载、有界缓存，不预读全部原生历史。历史读取单次最多 80 次原生 RPC，跨请求只携带最近 64 个游标作循环检测，预算耗尽保留准确续读位置。UI 缓存保留最近 16 个代理，关闭环境后可从原生历史恢复。

文件投影在共享预算外携带 `file_preview.complete`，比较原始文件列表和裁剪后的路径、类型、源文本及移动信息；缺项或截短必须按需读取详情。媒体扫描和文字输出共用有界 JSON 容器解码，识别 MCP content/result 包装及文本块中的序列化图片；普通 JSON 和描述文字保留。

滚动补偿使用版本专属的真实 Button key 标记新树：Desktop 的定位表不包含 Box key。rc.16 将人类滚动与测量观察者分成不同注册；原生内核会排除调用自己的注册，过期计时器或原始按钮闭包还可能屏蔽本插件的全部注册。滚轮仅排队并异步读取历史；Client 收到就绪令牌后发送一次消息，新 `ui.message` 分发在测量结束前保持活跃。令牌同时检查代理、页面代数和有效方向，切换代理及跳到最新会取消旧请求。

裁剪与添加分阶段测量；裁剪采用实际高度变化，前插优先使用保留消息的阅读标记位移，新树再采样以容纳原生叶节点稍后的布局。测量期间固定时间线快照，实时数据仍进入缓存，结束后按原首尾记录恢复窗口。rc.26 桌面采用 settleBeforeCommit：探测只读取坐标、保持原滚动偏移，标记与内容高度稳定后一次提交最终补偿。原生 Box 加载层覆盖会短暂错配的富文本布局，定位完成才撤下；采样被拒绝或无法稳定时恢复旧窗口再显示。结算期间的滚轮合并为当前加载动作，不积累后续翻页；终端保留原有持续滚动参照行为。每次显式打开代理和直接发送后都请求尾部定位。ui_* 内部请求不确认或消费 Claude 事件。

打开面板时每秒查询变动，无变化不重绘，未打开不读详情。工具展开状态与消息合并独立，展开不冻结消息、进度或终态答复。已有输出立即呈现，缺失详情异步读取，缓存重开不重复请求。桥接并行读取当前会话和环境设置；发送撞上在途轮询时完成后跟进一次。

实时内容增长需要跟随时，先建立尾部请求，再一次失效重画新内容及导航令牌；不先画内容、再决定是否跟随。处于跟随状态且没有待处理阅读测量时，`person/by:0` 只视为宿主布局通知，不取消跟随。真正上滚照常更新阅读意图并使迟到的尾部请求失效。state 订阅是定向绘制入口，轮询测试必须等待该入口绘制，不能靠测试自己调用 draw 来模拟自动更新。
面板匹配包含具体 requestId；使用公开 state 订阅定向更新，避免活动更新令主线程工具行和其他面板一起重绘。稀疏模型状态更新只修改实际存在的字段，不清空 UI 专用权限和用量；显式 null 仍会清除旧值。渲染回调构造组件并记录实际绘制窗口及预算，不执行滚动或历史读取；滚动恢复由导航动作触发。工具输入与输出按结构拆分，通过原生 Code 保留等宽和换行；延迟输出展开时请求 `ui_detail(view:'output')`，只有 `next_offset` 非空才提供下一页，原始调用单独折叠。元信息使用宿主 caption/footnote 字号。公开 Input 没有附件事件，Windows 选择文件与显式粘贴附件通过独立本机进程完成，剪贴板不被后台监视；附件显示名称有界、自动换行，真实路径不被缩短。

Desktop 使用公开 `e.props.scroll.bodyRows` 设置对话最小高度，中间消息区伸展，短对话的输入区仍在可用面板底部；长对话随宿主整体滚动。不读取私有 DOM，不重写宿主样式。输入区保持单层原生 Input。圆钮 Client 外壳与内部根 Box 均明确为 2lh，避免中间无固定高度容器使百分比高度失效；底栏按统一中心对齐。集成标题和子项采用相同间距，左侧细竖线仅是装饰，外层折线箭头可折叠整组，工具标签自身可展开输出。正文与工具组按侧栏密度排布。 只读核对 Claude Desktop ASAR 确认宿主使用 `h-full w-full p-lg` 固定内边距和 cell 行高取整；插件已到可用区域底部，不添加假 padding 或修改宿主，左右 footer 无法保证像素对齐。

分组折线箭头为原生 SVG；文字保留 Button，箭头用透明 Client 命中区域覆盖，指针与键盘事件仅切换当前代理的对应分组，过期状态点击不反转新状态。代理标记由固定 ID 的确定性散列选择图案，Desktop 使用多样 SVG，终端用对应字符；目录、标题、历史活动及主会话行共享该映射。不维护可被刷新裁掉的槽位表，不按活跃状态、名称或渲染顺序重排；不同 ID 可以共享图案，同一 ID 在重新打开或跨渲染生命周期时保持一致。无目标的等待事件使用中性时钟图标。传入消息的 85% 限宽属于无边框外层，气泡自身自动宽度、右对齐，避免短句被撑满。

标题与折线箭头位于零间距内层行，前置工具图标保持外层间距；箭头命中区从左侧排 SVG，减少父容器间距、原生 Button 内边距和图形空白叠加。代理名在主会话入口、面板标题和子代理活动行统一将首字母大写，仅转换显示文本，动作始终使用原 ID。

rc.17 删除可见历史加载按钮：接近边缘自动加载，等待时显示圈；测量标记放在零高度裁切容器中。导航 Client 保持在视口内，避免离屏区域被暂停；继续滚动不再直接取消窗口补入，位置由最新人类样本补偿。单一底部居中按钮使用原生 offset/bodyRows 跟随，稳定保留其 Client 和悬停节点；相同内容、尺寸及草稿复用整个内容树，只重建轻量外框。尾部定位用当前渲染版本的按钮 key 确认窗口，然后在滚动事件里使用整页的 `contentRows - bodyRows` 定位到底栏。手动下滚到最新窗口末端时恢复跟随，宿主单纯调整布局时保留阅读位置。浮动按钮的点击区域只占居中的 4×2 个字符单元，底栏两侧的控件可直接点击。

当前 Desktop 不渲染终端专用 Image。Windows 媒体读取通过系统 GDI+ 生成有界 JPEG 数据：缩略图 4,500 字节、放大预览 42,000 字节；桌面使用原生 Markdown 图片的数据 URL 通道，终端仍使用 Image。每页最多 8 图、总输出受桥接上限约束；原图链接保留。预览中的滚动不改变对话的保存位置，关闭通过新的注册分发恢复打开前的偏移，避免图片页高度改变后回到列表顶部。

rc.18 为每次翻页分配独立事务；跳转、切换代理或发送取消旧事务，旧测量和 finally 均不得回写新窗口。全部程序滚动经过同一队列，已取消的在途测量只保留当前偏移，随后才提交新的尾部定位。尾标记使用请求专属 key，等待新树出现后二次确认，避免把旧窗口末尾当作新末尾。同向未完成读取共用请求；短窗口和硬边界通过 Client 的 edge 消息主动续读，按窗口、游标和版本组成的进展 key 去重，无进展时不空转。测量标记在裁切容器内保留非空字形，保证宿主可测量的几何尺寸。

rc.19 在 invalidate 前调用滚动控制器 stage，保留变更前的几何与用户位置。本次布局交易中，几何同时改变的 person 事件视为宿主 resize/auto-clamp，不用其夹紧后的位置覆盖阅读锚点；同几何下的继续滚动仍更新用户意图。变更后采样至少跨过 96 ms，最多使用 0/32/64/128 ms 的有界重试；初次与显式跳底定位也等几何稳定，实时跟随仍允许用户立即取消。根 Box 裁切绝对定位子节点的溢出，防止旧 offset 的浮层扩大 scrollHeight；正常流内容和按钮居中跟随方式不变。桌面缩略图取消固定行高，点击覆盖层随实际图高；编码缓存最多 64 项，按文件大小、mtime、ctime 校验，共用并发请求、失败可重试，关闭时释放。

rc.20 校正实际 Desktop 契约：`gv` 不把 `contentRows` 放入 `props.scroll`，边缘判定改用 `ui.scroll` 的实际采样；`Tte` 可返回 `deny: the window moved meanwhile`，采样不代表提交成功，只有接受后才确认位置。原始 `hv/es` 仅在 props hash 改变时保存新输入，顶层的 `contentRows/keyed` 单独变化会丢失，普通 invalidate 仍读取旧几何。Desktop 定位前通过同 ID `ui.open` 在 `Codex` 与 `Codex ` 间交替，尾随普通空格被标题清理保留、HTML 显示折叠；保留 `rows:24/closeOnEscape:true` 并省略 focus，不更换面板、不挪动视口、不抢焦点。等待一个布局帧后重新测量，有界重试覆盖异步绘制；终端不走该兼容路径。禁止用 ZWSP 替代：实际标题清理会将其显示成替代字符。自动边缘进展令牌不再把单纯布局版本变化视为历史进展。

rc.21 普通边缘加载只接受滚动触发；render 自动 edge 仅限初次短页面补齐一批。访问同一边缘后锁定，稳定几何下离开该边缘再返回才重新触发，完成后的 150ms 布局稳定期不发新导航。首尾范围、cursor 变化不能解除锁定。

只读 Desktop 源码确认普通树可能整体替换，Markdown/Code holder 按全树 leaf 序号复用，而非公开 key，因此重绘可出现多阶段高度。前插在保留的第一组顶部放一个真实 Button 阅读标记，测量前后同标记的目标坐标差；下方内容变高不再算成上方新增。标记零高度、位于内容分页外且计入预算。新增期间 root minHeight 保留旧实测高度以防临时塌陷夹紧 viewport；稳定测量后移除。锚点采样以 0/32/64/128/256ms 有界再试，至少跨过 224ms 后按标记坐标稳定判定；用户滚动意图仍可更新参照。公共 Client 的桌面树不接受原生 Markdown/Code，未用它替换富文本组件，也未假设普通 key 能保留宿主 DOM。

## 缓存

父 Claude 的请求历史、系统提示词和工具描述均不被本插件重写。工具 schema 固定；ToolSearch 的生命周期交给宿主。读取当前可用快照是只读操作，Claude 的 cache_control 不作为正文复制。新 Codex 初始上下文有固定前置说明；后续保持同一线程并追加输入。

实际缓存读取和写入量来自 `thread/tokenUsage/updated`。压缩、模型切换、宿主升级和供应商缓存过期应与普通续接分组观察，不能用随机样例的一次命中替代验收。插件不发付费心跳维持缓存。

## 明确失败的边界

- 宿主不支持所需公开接口，或未返回合法消息数组。
- 无法无损映射的二进制附件、非法消息角色或非 JSON 工具证据。
- 超出传输硬限制的报文：JSON-RPC 帧 16 MiB、本机 HTTP 请求 64 MiB。它们是实际字节限制，不是模型上下文估算；不截断或擅自总结。
- 协议不支持、动作结果不明、过期审批、恢复仍超限、状态落盘失败。

这些边界会返回错误，不伪造成功、不静默改用 `none`，也不让模型代写昂贵的交接摘要。宿主正常的 4,096 条返回限制属于 `available` 的已声明语义，不被当作完整继承。

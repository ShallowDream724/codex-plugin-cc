# 0.2 开发范围

当前为 **0.2.0-rc.18 本地候选**。rc.17 仍在短窗口、连续上滚和跳转期间出现加载停滞。此轮对导航实行独立事务和串行滚动提交，跳转使旧导航失效；短窗口与硬边界由 Client 主动续读，按进展去重防空转；按实际绘制预算裁剪，取消按条目数频繁裁掉已读区。保留自动加载圈、桌面图片与预览位置恢复。用户确认本地使用无误后再发布 GitHub。状态格式仍为 version 1，升级保留代理登记、原生线程和用户暂停状态。

rc.15 中的媒体恢复：真实记录中的 event 图片 Base64 可能被截断；对已登记线程，按相同线程、轮次和调用 ID 从 rollout 的完整 `function_call_output` 恢复。读取器缓存偏移而非图片内容，限制为 32 个线程、每线程 2,048 个调用、单次扫描 256 MiB、单行 32 MiB，不载入整个文件；恢复失败仍显示提示。

rc.16 的历史导航：保留有界窗口及缓存，普通滚轮不等待读取。只读实际 2.1.325 内核确认自身 hook 重入过滤是 rc.15 测量失效的根因；测量观察者独立注册，计时器只排队，由 Client 消息开启新的注册分发，维持测量期间的调用身份。前插按真实高度差保留阅读位置；用户继续滚动时按该事件已包含的高度补偿。返回最新按钮恢复视口底部居中跟随，同一内容版本的滚动帧复用消息、工具及图标树，只更新外层位置，无额外滚动重绘计时器。禁止 Computer Use 操控 Claude；只读源码和隔离浏览器验证，不修改宿主。

未发布开发修复：补齐后代结束与迟到根结束的等待唤醒，并复查空 claim 与 idle 判断之间的新事件。保留现有 25 秒长轮询与 timeout 语义，不新增后台查询。此修复包含在 rc.13 本地安装候选中。

未发布通知改动：主会话工具批次结束后可以收到 Codex 结果注记，并由下一模型步骤读取；不等完整 Claude 轮次结束，不中止任务。只有正常结束且没有后续步骤时才补一次不重复正文的唤醒提示；主动停止不触发它。与 `wait_agent` 共用交付租约和实际保留内容确认，保留原私人轮次隔离。后台观察周期不变，批次及正常完成增加事件边界检查。验证只使用模拟记录和只读宿主源码；此改动包含在 rc.13 本地安装候选中。

文件变更和跟随滚动修复：原生 add/delete 的 `diff` 实际是完整文件内容，update 才是 unified diff；按记录类型统一规范化，保留旧格式 `content`/`unified_diff`，创建不再统计正文的行首符号。重命名按确切元数据识别，不随意剥离正文。大 Diff 使用有界结构化行页，保持行号和增删色，未知记录不编造统计。实时记录合并后在跟随状态调度到底部，用户主动滚动使迟到的滚动任务失效，工具展开不永久关闭跟随。

未发布界面改动：长消息和通信正文一次展开或收起；不超过 48,000 个 UTF-16 代码单元时完整显示原生 Markdown，超限则显示安全预览和完整临时 Markdown 文件链接，重开复用缓存。普通工具长输出仍分页。所有正文使用原生 Markdown，展示副本保守修复中文粗体闭合并保护代码、数学与链接；原始历史和复制不变。仅有完成证据的原生 `final_answer` 提供完整原文复制，不再猜测旧记录的最终答复。图片在对应工具展开后按需读取，支持同面板放大及返回；待发送和已发送的 PNG 附件也可预览。正文展示不改变通信内容，不读取后代完整对话。这些改动包含在 rc.13 本地安装候选中；分支列表未实现，分支功能推迟。

待研究的 APP 进程复用：本机 CLI 的 `app-server proxy --help` 明确提供连接现有 app-server 控制 socket 的入口；[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server) 描述 stdio、WebSocket 和 Unix socket 客户端连接，以及由客户端处理动态工具调用。这证明共享 server 的传输机制存在，尚不能证明 ChatGPT/Codex APP 开放了对应端点、允许第二个界面控制同一线程，或会为外部连接执行 APP 的浏览器、Computer Use 和内容准备服务。尚未连接 APP 现有进程、测试双客户端或改变运行配置；不得把此构想视为当前报错的已确认修复。

状态：0.2.0-rc.12 将初始任务记录绑定准确首轮，修复与原生消息重复显示；工具详情保留参数、输出和业务信息，移除重复完成状态和传输元数据。三种上下文来源持久标记并在侧栏显示；真实 Codex CLI 的本机模拟服务探针确认继承窗口不进入展示历史，实际任务和压缩记录仍可分页读取。协作指引明确通知与待答请求的区别。组件检查不代替 Desktop 绘制验收；开发不发真实模型请求。

## 已确认行为

- 九个模型工具保持明确职责。`followup_task` 接受已登记代理、原生线程 ID 和 `codex://threads/<id>`；外部历史原样续接，不注入 Claude 快照。
- `close_agent` 保留显式控制，增加指定集合或全部排除保留集合的批量关闭。保留原生历史，清理已关闭代理的待交付事件；活动代理不得误关。
- 同一 Claude 会话默认最多五个直接活动 Codex 任务，用户可调至七个。历史登记不占活动名额；原生后代由所属 Codex 负责。
- 权限默认完全访问，用户设置控制，Claude 工具参数不提供权限选择。支持原生自动审查和请求批准。
- `role: default` 是 Luna medium、任务独立上下文、单轮只读探子；普通 Codex 保留多轮、子代理和原生生图能力。
- 模型列表沿用 Codex 当前目录，返回原始描述和支持档位，不静态屏蔽新模型；选型提示集中维护。
- 用户界面只呈现直接代理：可点击的名称、开始/完成/需要处理记录，过程按需展开。工具过程不进入 Claude 事件队列。
- UI 以代理/轮次/事件 ID 定位；长输出按需读取、有界缓存、合并刷新。未查看详情时不轮询详情。原生后代只显示委派记录。
- 不修改 Claude Code、不调用模型生成进度摘要、不估算或额外裁剪继承上下文，不重写对话和工具定义来刷新 UI。
- 独立 `/codex-stop` 命令立即停止当前会话全部 Codex 子树，不增加按钮、不绑定 Claude 本轮停止；重启不自动续跑。用户停止事实仍通知 Claude；侧栏直接对话及其自动结果不主动转发。
- 官方桌面与浏览器能力依赖已安装插件、运行中的宿主和实际连接，不能仅凭列出工具声称可操作。不会自动打开 Codex App。

## 模块责任

- 控制器：权限、活动名额、预设、续接、关闭与回执边界。
- 活动视图：直接代理的只读过程投影和按需渲染，用户操作走独立的内部控制入口；两者均不确认 Claude 的事件。
- Claude hooks：短工具契约、宿主上下文、交付确认和 UI 整合。
- 指引：`config/guidance.json` 和 `skills/codex-delegation/SKILL.md`；用户最终审阅后再发布。

## 验证重点

并发派发/续接不可突破名额；异常不能泄露名额；外部活跃线程不得双写；关闭和迟到事件不复活；近同时事件精确交付；UI 与模型事件完全分离；大输出/长列表有界；角色与模型描述一致；权限切换不能静默沿用旧 helper 配置。

## 当前范围之后再讨论

用户直接操作已纳入当前版本，未增加模型工具。是否强制 Codex App 常驻、能否复用 App 的进程仍留待后续核查，当前不改变进程架构。

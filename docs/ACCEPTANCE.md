# 手动验收

真实 Claude/Codex 调用与缓存命中留给用户操作。下面的步骤不会在安装或测试时自动执行。

1. 使用原有 Claude Code 安装，记录内核和 Codex CLI 版本。插件不需要修改宿主。Desktop 应单独确认 mods 和当前消息读取接口可用，不能用 CLI 的检查结果替代。
2. 加载插件与 `codex-delegation` skill，让 Claude 用 `none` 分配一个很小的只读任务。确认返回代理 ID，等待后取得结果，界面有可点击的开始与完成记录。
3. 在父会话中提供一个随机标记、读一个含另一随机标记的文件，并产生一次工具结果。用 `available` 新建 Codex，让它报告这些事实。父 Claude 只输出任务，不复述标记或交接历史。检查快照统计和结果是否一致。
4. 在同一 Claude 会话内自然或手动压缩多次，期间增加、替换要求。再次用 `available` 分配任务，确认在返回范围内使用当前摘要、保留消息和压缩后的内容，没有恢复已删除旧要求，也没有把几轮摘要重复拼接。
5. 给同一 Codex 发送补充消息，再 followup。确认 thread ID 不变、初始快照未重复注入。空闲 send_message 只排入原历史，followup 才启动。
6. 让 Codex 遇到一个需要取舍的小问题。确认 Claude 收到 question、按精确 ID 回答，并由原 turn 继续；需要用户的新决策才问用户。审批不要因测试而自动接受。
7. 让 Codex 自行使用原生子代理。Claude 不应收到后代的工具输出或完整过程；必要后代问题仍能被回答。
8. 在 Codex 工作时中断等待，再恢复等待。任务应继续。随后中断代理，确认不会自动续跑；显式 followup 能恢复原历史。
9. 查看状态文件中的真实 `tokenUsage.last` 与 `total`，比较同一线程初始调用和后续短消息的 `cachedInputTokens` / `cacheWriteInputTokens`。Claude 一侧查看其实际 cache read/write 统计。将发生 compact 的轮次单独记录。
10. 关闭并重开宿主，用原 Claude 会话列出代理后 followup，确认恢复原 Codex thread。最后在实际使用的 Desktop/终端分别验收加载与通知。
11. 确认 available 的新建结果含首尾预览及消息序号，预览省略不影响 Codex 得到的窗口内容。用 `timeout_ms` 短暂等待正在工作的代理，确认只结束等待；不再需要的失败代理用 `close_agent` 清理，随后列表不再显示它。
12. 在最后一个完成结果已显示后退出并恢复同一 Claude 会话，再短暂等待，确认不重复返回刚才的完成事件。不要为一个会话并行调用多个 wait；第二次并发调用会说明已有等待者，不另领同一批事件。
13. 用 `role: default` 分配一次资料定位和事实核验任务，确认模型/档位为预设值，不导入父历史、不改文件、不生图、不派生。普通 Codex 仍能用自己的原生子代理；已有用户角色配置保持原样。
14. 按实际工作需要验证活动名额：达到默认 5 个后新增任务明确告知已满；已完成登记不占名额。批量关闭用 all/except 保留要复用的代理，活动代理不被误关。无需为了测试而无意义派发五个付费任务，可在真实工作中检查。
15. 用闲置原生线程的深链接继续一个小任务，确认 thread ID/cwd/历史延续，Claude 快照没有重复注入。活跃外部对话不得双写；检查 client_tools_unavailable，原客户端专属动态工具不可用时必须明确报告。
16. 在 CLI 与 Desktop 分别点击多个中文/英文长名字、切换代理、展开合并工具组、阅读旧页和长输出，再关闭面板。确认名称入口都保留、页面不会串代理、正在阅读时不强制跳底；`/codex-agents` 可作为键盘入口。展开仅改变 UI，不给 Claude 增加工具过程。
17. 保持 Codex App 运行，用实际任务验证所需浏览器/电脑能力。先用 doctor 区分注册状态与宿主连接，不能把仅列出 cua_repl 视为已经能操作。App 未运行时不依赖这项能力。图像生成只在实际需要时验收保存路径和像素尺寸，不假设固定上限。
18. 用户可将权限改为 auto-review 或 ask，重启当前 helper 后验证原生行为；Claude 的派发参数不出现权限选择。测试不得使用真实破坏性操作。
19. 从代理详情直接发送消息，确认运行中的任务收到补充指导，空闲任务通过 “发送并继续” 沿原历史继续；Claude 收到用户消息正文与投递结果。切换代理后草稿不串位，投递未知时保留草稿且不自动重发。
20. 在详情点击 “停止”，确认该代理及其后代停止、其他代理继续；未收到确认时显示停止中或未确认。Claude 不得自行发消息、续接或回答待审批请求来绕过用户停止。重开会话、关闭后用深链接接入均保留暂停意图；用户确认停止后可用直接消息恢复。
21. 用实际工作中的 FastCtx/MCP、命令、网页搜索、文件修改、生图和压缩记录核对展示。子代理只出现身份和开始/完成状态，不递归展开其过程。核对长文件 diff 计数及前后分页；已有 Markdown 公式、Mermaid 交给宿主渲染，终端源码应完整可读；HTML 产物不被误标为可执行的内嵌组件。
22. 点击附件按钮选择图片和普通文件，确认可删除待发送附件、只发附件、保留失败草稿；图片进入原生图片输入，普通文件由 Codex 按路径读取。核对中文路径、取消系统选择框和无选择器时的路径输入。Claude 只收到附件元数据及投递结果。输入区权限/模型/推理档位正确，上下文比例仅在收到原生 usage 后出现。
23. 展开多文件修改，确认每个文件对应自己的 diff、复制操作及分页；完整差异显示原生 diff，分页片段不会冒充完整差异。连续相同工具调用可以合并，不同工具或服务器不会误用同一标题。
24. 已完成任务的详情保持打开，观察底栏是否稳定；展开工具应以等宽格式保留命令和输出换行，导航/消息/工具/输入区应有清楚层级。保持工具展开后直接发送消息，确认自己的消息、后续进度和最终答复继续出现；展开内容和缓存保留，后台更新不强制跳底。从旧页发送则应回到最新消息。在当前宿主上分别验收窄栏与宽栏、短对话输入区贴底及底栏对齐，不以原生组件校验通过代替实际视觉结果。
25. Windows 截图后点击“粘贴附件”，以及复制文件后点击同一入口，确认附件出现并可移除；剪贴板没有图片或文件时显示明确提示。当前插件 Input 不支持图片 Ctrl+V 或拖放，不将这两项误报为已实现。

不要为了验收超限而无意义地生成几十万 token。错误、压缩事件、失败恢复、旧请求 ID、消息截断和重复交付等边界已有本地模拟测试；真实运行中遇到时再核对实际行为。

发现问题时，记录插件版本、Claude 内核版本、Codex CLI 版本、代理/thread ID 和状态错误码。状态默认位于 `~/.claude/codex-subagents/<session-hash>/agents.json`，不要公开真实会话、凭据或完整工具结果。
